计算机内部并非只有一个“时钟”。理解它，可以先分清三个问题：

- **电路什么时候进行下一步？**——靠时钟信号。
- **从刚才到现在经过了多久？**——靠硬件计数器。
- **现在是几月几日几点？**——靠操作系统维护的时间，并通过外部时间源校准。

它们通常都依赖本地振荡器，但用途不同。

### 1. 最底层：怎样产生稳定的“滴答”？

常见方法是**石英晶体振荡器**。

石英具有压电效应：施加电压会产生机械形变，机械形变也能产生电信号。把晶体放入带放大、反馈的电子电路中，就能维持接近其谐振频率的周期振荡，再整形成数字电路可用的时钟信号。

这里有三个环节：

| 环节                 | 作用                     |
| -------------------- | ------------------------ |
| 石英晶体             | 提供相对稳定的谐振频率   |
| 振荡电路             | 补偿能量损耗，维持振荡   |
| 整形、分频和倍频电路 | 生成各部件所需的时钟信号 |

**晶体本身不需要以 CPU 的 GHz 频率振动。**芯片可以用锁相环 PLL，把较低的参考频率变成较高频率。

例如，简化地看：

$$ f_{\mathrm{CPU}}=M f_{\mathrm{参考}} $$

假设参考频率为 $100\,\mathrm{MHz}$，倍频系数为 40，就能得到 $4\,\mathrm{GHz}$。真实处理器有多个时钟域，核心、内存控制器、接口等可以使用不同频率；Intel 的处理器文档也明确区分多种参考时钟及其驱动的部件。[13th Generation Intel® Core™ Processors](https://edc.intel.com/content/www/br/pt/design/products/platforms/details/raptor-lake-s/13th-generation-core-processors-datasheet-volume-1-of-2/002/007/005/clock-topology/https%3A%2F%2Fedc.intel.com%2Fcontent%2Fwww%2Fbr%2Fpt%2Fdesign%2Fproducts%2Fplatforms%2Fdetails%2Fraptor-lake-s%2F13th-generation-core-processors-datasheet-volume-1-of-2%2F002%2F007%2F005%2Fclock-topology%2F/?utm_source=chatgpt.com)

### 2. 时钟信号有什么作用？

**它为同步数字电路规定“何时接收新状态”。**

例如，一段计算电路可以理解为：

1. 寄存器输出当前数据。
2. 数据经过加法器等组合逻辑，信号逐渐稳定。
3. 下一个有效时钟沿到来，寄存器保存计算结果。

时钟周期必须给信号传播留出足够时间。粗略地说：

$$ T_{\mathrm{时钟}} \geq T_{\mathrm{组合逻辑延迟}} + T_{\mathrm{寄存器时序要求}} + T_{\mathrm{裕量}} $$

因此，频率不能无限提高。时钟过快，结果还没稳定，寄存器就已经采样，可能产生错误。

另外，**一个时钟周期不等于执行一条指令**。现代 CPU 有流水线、并行执行和缓存等待，一条指令可能经历多个周期，一个周期也可能完成多条指令。

### 3. 怎样从“滴答”得到“经过了多久”？

让一个硬件计数器随着时钟递增即可。

假设计数器频率为 $f$，两次读取分别得到 $C_1,C_2$，那么：

$$ \Delta t=\frac{C_2-C_1}{f} $$

例如，一个 $10\,\mathrm{MHz}$ 计数器增加了 500 万：

$$ \Delta t=\frac{5\times10^6}{10^7}=0.5\text{ 秒} $$

操作系统使用这类硬件作为 **clocksource（计时源）**。另有 **clockevent（时钟事件设备）**，负责在某个未来时刻产生中断，用于超时、唤醒和调度。[The Linux Kernel documentation](https://docs.kernel.org/timers/timekeeping.html?utm_source=chatgpt.com)

| 机制         | 回答的问题       | 典型用途                   |
| ------------ | ---------------- | -------------------------- |
| 硬件计数器   | 经过多少时间？   | 性能测量、维护系统时间     |
| 定时器、中断 | 到指定时刻了吗？ | 线程唤醒、超时、调度       |
| 日历时间     | 现在是什么日期？ | 日志、文件时间戳、定时任务 |

**CPU 变频也不意味着电脑时间随之变快或变慢。**现代系统会选择适合计时的时钟源；例如支持 invariant TSC 的处理器，其计时频率独立于核心实时运行频率。

### 4. 关机以后，电脑为什么还知道时间？

通常依靠 **RTC：实时时钟（Real-Time Clock）**。

RTC 是低功耗计时电路，常使用 $32\,768\,\mathrm{Hz}$ 的石英晶体，因为：

$$ 32768=2^{15} $$

连续进行 15 次二分频，就能得到每秒一次的节拍。这个频率也是石英钟表的常见选择。[NIST](https://www.nist.gov/pml/time-and-frequency-division/timekeeping-and-clocks-faqs?utm_source=chatgpt.com)

RTC 由备用电池或其他备用电源供电，在电脑关机时继续计时。典型过程是：

- **启动时**：操作系统读取 RTC，获得一个初始日期时间。
- **运行时**：操作系统使用适合高精度计时的硬件计数器维护时间。
- **联网后**：根据时间服务器修正系统时间，并可按系统策略更新 RTC。

因此，系统运行时通常不需要反复读取 RTC 来获得每一个时间值。RTC 与操作系统维护的系统时间是两个不同层次。[kernel.org](https://www.kernel.org/pub/linux/docs/man-pages/book/man-pages-6.12.pdf?utm_source=chatgpt.com)

### 5. 为什么还要校准？

因为**本地振荡器并不完全准确**。

温度、制造误差、老化、电源等因素都会影响频率。如果电脑认为振荡器恰好是 $f_0$，实际却是：

$$ f=f_0(1+\varepsilon) $$

那么经过真实时间 $t$，计时误差近似为：

$$ \Delta t=\varepsilon t $$

例如，假设频率误差为 $20\,\mathrm{ppm}$，也就是百万分之二十，一天累计误差约为：

$$ 86400\times20\times10^{-6} =1.728\text{ 秒} $$

这里要区分两种误差：

| 误差     | 例子          | 修正目标           |
| -------- | ------------- | ------------------ |
| 时间偏移 | 现在慢了 3 秒 | 把当前读数对准     |
| 频率偏差 | 每天又慢 1 秒 | 修正时间增长的速率 |

只把时间拨对一次，无法解决持续走快或走慢的问题。

### 6. 联网校时怎样排除网络延迟？

常见方案是 **NTP，网络时间协议**。

不能直接把服务器发来的“当前时间”照抄过来，因为消息到达时，时间已经过去了。

NTP 使用四个时间戳：

| 时间戳  | 事件           | 使用哪一端的时钟 |
| ------- | -------------- | ---------------- |
| $t_1$ | 客户端发送请求 | 客户端           |
| $t_2$ | 服务器收到请求 | 服务器           |
| $t_3$ | 服务器发送回复 | 服务器           |
| $t_4$ | 客户端收到回复 | 客户端           |

由此估算服务器相对客户端的时间偏移：

$$ \theta= \frac{(t_2-t_1)+(t_3-t_4)}{2} $$

以及网络往返延迟：

$$ \delta=(t_4-t_1)-(t_3-t_2) $$

偏移估计依赖去程与回程延迟近似对称；路径不对称会造成误差。实际系统还会多次测量、过滤样本，并结合多个时间源进行判断。[ntp.org](https://www.ntp.org/reflib/stamp/?utm_source=chatgpt.com)

校准后，操作系统可以：

- **直接调整时间**：适用于偏差较大等情况。
- **缓慢调节走时速率**：逐渐消除偏移。
- **估计长期频率偏差**：改善两次同步之间的准确度。

普通电脑联网校时通常调整的是**软件如何把计数值换算成时间**，不需要改变 CPU 的运行频率。[The Linux Kernel documentation](https://docs.kernel.org/timers/timekeeping.html?utm_source=chatgpt.com)

这也解释了为什么程序测量耗时通常应使用**单调时钟**：日历时间可能因校时被调整，而测量“任务执行了多久”需要避免这种跳变。

### 7. 与铯原子钟是什么关系？

**石英振荡器负责本地持续计时；原子钟为时间单位和准确走时提供基准。**

目前，SI 中的“秒”定义为：

> 铯-133 原子未受扰动基态超精细跃迁所对应辐射的 9,192,631,770 个周期的持续时间。[BIPM](https://www.bipm.org/en/si-base-units/second?utm_source=chatgpt.com)

注意，这说的是**对应跃迁的电磁辐射频率**，不是铯原子在空间里机械振动这么多次。

铯原子钟的核心也是一个反馈控制过程：

1. 电子设备产生接近目标频率的微波。
2. 用微波作用于铯原子。
3. 测量原子的跃迁响应。
4. 根据响应产生误差信号，修正电子振荡器。
5. 将锁定后的频率用于计时。

也就是说，**原子提供可复现的频率参照，电子电路负责产生、控制和输出信号**。铯喷泉钟正是通过原子跃迁来校准微波频率。[NIST](https://www.nist.gov/pml/time-and-frequency-division/time-realization/cesium-fountain-atomic-clocks?utm_source=chatgpt.com)

普通电脑通常没有铯原子钟，而是通过时间服务间接获得原子时间：

| 层次                     | 主要职责                         |
| ------------------------ | -------------------------------- |
| 原子钟与计量机构         | 实现时间、频率基准，维持标准时间 |
| 时间传递系统、时间服务器 | 将标准时间传递出去               |
| NTP 等同步机制           | 估算电脑与参考时间的偏差         |
| 电脑本地振荡器和计数器   | 在同步之间持续计时               |

NIST 的时间服务就是将其维持的标准时间通过互联网等渠道提供给用户设备。实际授时体系使用多种原子钟，并不要求每台服务器直接连接一台铯钟。[NIST](https://www.nist.gov/atomic-clocks/how-we-tell-time/how-does-atomic-time-get-your-computer?utm_source=chatgpt.com)

还要抓住一个区别：**准确的频率告诉你“一秒有多长”，日期时间还需要知道“从哪个起点累计了多少秒”**。所以，一个走得非常准、但初始日期设错的钟，仍然会显示错误时间。
