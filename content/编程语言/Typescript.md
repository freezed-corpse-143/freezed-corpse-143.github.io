
# const - 变量绑定不可变

变量名不能被重新赋值

# readonly - 属性/成员不可变

readonly 是类型层面的，用于修饰类的属性、接口属性、数组/元组

# any

表示“关闭类型检查”，可以任意读写、调用，没有安全保障

# unknown

表示类型未知，可以赋值给它，但使用前必须收窄类型

# 工厂函数 VS 构造函数

| 维度               | 工厂函数                            | 构造函数                                  |
| ---------------- | ------------------------------- | ------------------------------------- |
| **调用方式**         | 普通函数调用 `createPerson()`         | 必须用 `new` 调用 `new Person()`           |
| **`new` 关键字**    | 不需要，用了反而出错                      | 必需（否则 `this` 指向全局/undefined）          |
| **返回值**          | 显式 `return` 一个对象                | 默认返回 `this`（若返回对象则覆盖）                 |
| **`this` 绑定**    | 不依赖 `this`，可用闭包                 | 依赖 `this` 指向新实例                       |
| **原型链**          | 默认指向 `Object.prototype`（除非手动设置） | 实例的 `__proto__` 指向 `Person.prototype` |
| **`instanceof`** | 通常失效（除非手动设置原型）                  | `p2 instanceof Person === true`       |
| **命名约定**         | 小驼峰 `createXxx`                 | 大驼峰 `Person`                          |
| **方法共享**         | 每次调用都创建新方法（除非用外部对象/闭包）          | 方法写在 `prototype` 上可共享                 |
如何选择？

**用工厂函数当：**
- 需要私有变量/闭包状态
- 需要根据条件返回不同类型的对象
- 不想暴露 `this` / `new` 的心智负担
- 函数式风格、组合优于继承

**用构造函数（或 ES 6 `class`）当：**
- 需要 `instanceof` 做类型判断
- 需要原型链继承、方法共享节省内存
- 与现有基于类的库/框架集成
- 团队习惯 OOP 风格
