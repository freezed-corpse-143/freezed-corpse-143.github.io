# 异构与慢节点：为什么大家要等一个人

[返回总览](./分布式大模型.md)

## 异构不只是显卡型号不同

一个集群中的 GPU 算力与显存、CPU 供数速度、网卡带宽、存储和软件环境都可能不同。即使 GPU 型号相同，不同节点的拥塞、散热或数据读取也会让实际速度不同。

**同步训练**的一步通常需要参与者在某些同步点汇合：快卡已完成工作却等待慢卡，这个拖慢全局进度的参与者称为 **straggler（慢节点/慢工作进程）**。慢不等于故障；网络退化、数据倾斜和异常长序列也会导致偶发慢步。

## 两个具体例子

- 两个数据并行进程分别用 80 ms、140 ms 完成本地计算。同步点必须等较慢者；给快进程加速几乎不改变 step 时间。
- MoE 路由把多数 token 送到少数专家。负责热门专家的 GPU 忙碌，其他 GPU 等待；这叫负载不均衡，即使所有 GPU 型号一样也会发生。

先比较每个进程的 step 耗时和等待时间，再检查是计算、数据、网络还是专家负载造成差异。可通过任务放置、数据负载均衡或将适合的进程编成同速组来缓解；不要一见慢步就假设换 GPU 可以解决。

## 软件、地域也会让同一工作负载表现不同

**软件异构**例如节点上的驱动、通信库版本或算子实现不同：即使 GPU 型号相同，性能和可用功能也可能不同；不兼容的版本还可能导致作业无法启动。**地理异构**指节点分布在不同机房或数据中心，跨地域链路通常比节点内互连延迟高、带宽约束更强，甚至有数据不能跨地域传输的要求。这些差异不能靠“每台机器发同样多的 token”就消除。

**负载均衡**是让关键路径上的工作量和完成时间尽量接近；**任务放置**是决定哪些进程、专家或数据放到哪些设备。例子：8 个 MoE 专家分在两张卡上，若热门专家全在 A，B 即使空闲也不能代算 A 的权重；调整专家放置/路由负载才可能缩短同步等待。相反，如果瓶颈是跨机架网络，把原本同节点频繁交换数据的进程拆到不同机架可能更慢。先找出是资源能力差、工作量偏斜，还是物理链路造成的慢节点，再做放置或均衡。
