**DeepSpeed 的 ZeRO Stage 1 / 2 / 3**，它们是三个逐步叠加的显存优化阶段。

核心思想：**数据并行中，每张 GPU 原本重复保存的训练状态，可以分片保存到多张 GPU 上。**

|模式|模型参数|梯度|优化器状态|
|---|---|---|---|
|普通数据并行 DDP|每卡完整|每卡完整|每卡完整|
|**ZeRO-1**|每卡完整|每卡完整|**分片**|
|**ZeRO-2**|每卡完整|**分片**|**分片**|
|**ZeRO-3**|**分片**|**分片**|**分片**|

三个阶段分别增加优化器状态、梯度、参数的分片。[DeepSpeed](https://www.deepspeed.ai/docs/config-json/?utm_source=chatgpt.com)

先理解需要存什么。训练一个参数 $w$，通常还需要：

- **参数**：$w$ 本身。
- **梯度**：$g=\partial L/\partial w$。
- **优化器状态**：例如 Adam 的一阶动量 $m$、二阶动量 $v$；混合精度训练通常还有 FP 32 主参数。

所以，训练显存远不止“模型权重大小”。

**① ZeRO-1：把优化器状态分给各张卡**

假设有 4 张 GPU，每张卡仍保存完整模型、处理不同的数据，但只负责约四分之一参数的优化器状态和更新。

一次训练可以概念化为：

1. 每卡用完整模型进行前向、反向计算。
2. 跨卡汇总梯度。
3. 各卡更新自己负责的参数部分。
4. 交换更新后的参数，让各卡重新拥有相同的完整模型。

**为什么能拆？** Adam 更新某个参数时，主要需要这个参数的梯度和对应的 $m,v$，无需其他参数的优化器状态。

**② ZeRO-2：进一步把梯度也分片**

既然每张卡只更新部分参数，那么梯度汇总后，**它只需要保留自己负责更新的那部分梯度**。

通常通过 Reduce-Scatter 一类的通信完成：

> 先将各卡针对相同参数的梯度求和或平均，再把不同参数对应的结果分给不同的卡。

各卡用自己的梯度分片和优化器状态分片更新参数，随后交换更新后的参数。

注意：**梯度分片不代表每张卡只计算四分之一模型的反向传播。** 每张卡仍针对自己的数据执行完整模型的计算，只是不长期保留完整梯度。

**③ ZeRO-3：进一步把模型参数也分片**

这时每张卡平时只保存自己的参数分片。但计算某一层时，需要这一层的完整参数，怎么办？

**用到时临时收集，用完后释放。**

例如计算某个线性层：

1. 通过 All-Gather 收集该层所需的参数。
2. 执行本卡数据上的计算。
3. 根据调度策略释放临时完整参数，只保留本地分片。
4. 反向传播时按需再次收集参数，并归约、分发梯度。

实际实现会结合预取、缓存和通信计算重叠。因此，**ZeRO-3 的参数是常驻分片，计算期间会临时展开**。[DeepSpeed 0.19.9 documentation](https://deepspeed.readthedocs.io/en/latest/zero3.html?utm_source=chatgpt.com)

用公式看区别最直接。设完整模型的参数、梯度、优化器状态分别占 $P,G,O$ 字节，共 $N$ 张数据并行 GPU，则理想情况下：

| 模式     | 每卡常驻模型状态显存  |
| ------ | ----------- |
| DDP    | $P+G+O$     |
| ZeRO-1 | $P+G+O/N$   |
| ZeRO-2 | $P+(G+O)/N$ |
| ZeRO-3 | $(P+G+O)/N$ |

这些公式**不包含激活、通信缓冲区、临时收集的参数和算子工作区**，不能直接当作实际峰值显存。

可以这样记：

> **ZeRO-1：分摊更新模型所需的状态。**  
> **ZeRO-2：再分摊更新所需的梯度。**  
> **ZeRO-3：连模型参数本身也分摊。**

它们解决的是**数据并行的状态冗余**；Stage 越高，显存通常越省，但通信和调度成本也更需要关注，训练速度不一定更快。
