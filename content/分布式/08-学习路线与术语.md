# 学习路线：把分布式大模型串起来

[返回总览](./分布式大模型.md)

## 沿着一次训练 step 阅读

1. **显存**：权重、激活、梯度能否放下？先读[显存与模型并行](./01-显存与模型并行.md)。
2. **计算**：数据到达 GPU 后有多少时间真正在做模型计算？读[计算与利用率](./02-计算与利用率.md)。
3. **交换**：多卡在什么时候传参数、梯度或 token？读[跨卡通信](./03-跨卡通信.md)。
4. **等待**：为什么同一同步点有人先到、有人后到？读[异构与慢节点](./04-异构与慢节点.md)。
5. **放置**：这些参与者在同一节点还是跨交换机？读[网络拓扑与放置](./05-网络拓扑与放置.md)。
6. **恢复**：卡掉线或数值失控后怎样继续？读[故障与检查点](./06-故障与检查点.md)。
7. **上线**：用户请求如何生成 token、缓存注意力状态？读[推理服务与 KV 缓存](./07-推理服务与KV缓存.md)。

## 一句话辨认常见词

| 词 | 先问什么问题 |
| --- | --- |
| DP / TP / PP / CP / SP / EP | 数据、层内张量、层、上下文、序列激活或专家，究竟拆了哪个维度？ |
| ZeRO / FSDP | 哪些训练状态不再在每个数据并行进程中完整常驻？ |
| Collective / NCCL | 多个 GPU 要完成哪种集体数据交换？ |
| Straggler | 谁让其余进程卡在同步点？ |
| Checkpoint | 是否存够恢复训练所需的状态，且状态是否可信？ |
| KV cache | 推理时怎样复用历史 token 的注意力计算？ |

这不是按产品或论文划分的技术清单，而是从“装得下 → 算得动 → 传得快 → 等得少 → 出错能恢复 → 用户等得起”逐步提出问题。原文在[分布式大模型总览](./分布式大模型.md)中保留完整脉络。
