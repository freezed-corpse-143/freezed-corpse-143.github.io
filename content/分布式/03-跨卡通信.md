# 跨卡通信：GPU 之间到底交换什么

[返回总览](./分布式大模型.md)

## 通信有两个成本

**延迟**是消息开始到完成的时间；**带宽**是稳定传输时每秒能搬多少数据。小消息通常怕启动延迟，大消息更受带宽约束。设备越多、交换越频繁，等待通信越可能超过本地计算。

节点内的 GPU 可能经 NVLink/NVSwitch 通信；跨节点通常经过网卡和交换机，常见网络有 InfiniBand 或基于以太网的 RoCE。PCIe 是主机和设备常用互连；RDMA 允许网络传输减少 CPU 参与，GPUDirect RDMA 在受支持的软硬件配置下让网卡更直接地访问 GPU 内存。**这些是路径或机制，不是保证任何两卡之间都同速的承诺。**

## 常见集体通信

设四张卡分别有值 $1,2,3,4$：

| 操作 | 发生什么 | 常见用途 |
| --- | --- | --- |
| AllReduce | 求和后每卡都拿到 10 | DP 同步梯度 |
| AllGather | 收集各卡不同片段，每卡获得完整结果 | 分片参数的临时聚合 |
| ReduceScatter | 先按片段归约，各卡只得到自己负责的片段 | 分片梯度 |
| Broadcast | 一张卡的数据发给其余卡 | 分发状态 |
| All-to-All | 每卡按目的地发送不同片段，并接收其他卡发来的片段 | MoE token 发往对应专家 |

**Ring**（环形）和 **Tree**（树形）是组织通信的算法/拓扑方式，不是与 AllReduce 并列的数据操作。NCCL 是 GPU 间实现这些集体通信的常用库；调用 AllReduce 不代表通信免费。

MoE 的专家散落在不同 GPU 上时，先把 token 发给专家，计算后还要送回原位置；这种 All-to-All 对跨节点带宽、负载均衡尤其敏感。

## 一条数据从 GPU 到另一台机器的 GPU

不同互连负责不同距离，不是所有数据都必经下面每一种设备：

| 名词 | 它是什么 | 直观用途 |
| --- | --- | --- |
| PCIe | 主机内的通用高速扩展总线/协议，连接 CPU、GPU 和网卡等设备 | CPU 与 GPU 传数据、设备经主机交换数据；并非每次 GPU-GPU 传输都必须绕过 CPU 内存 |
| NVLink | NVIDIA 的 GPU 高速互连技术；实际是否直连取决于机器配置 | 同节点 GPU 之间交换张量 |
| NVSwitch | 连接多张 GPU 的交换芯片/系统，使配套 GPU 能经高速互连互通 | 节点内多 GPU 交换，而不是每两张卡都独立布一条线 |
| NIC | Network Interface Card，网卡；把节点接入网络 | 跨节点传输 |
| Leaf / Spine | 数据中心交换网络的接入层/汇聚层角色 | 不同机架/节点经交换网络互通 |
| InfiniBand / RoCE | 两类常见的高性能网络方案；RoCE 在以太网上承载 RDMA | 跨节点通信 |

**例子**：两张同节点 GPU 若有可用 NVLink 路径，交换可能走 NVLink/NVSwitch；若只有 PCIe 连接，则要看实际 PCIe 拓扑；跨节点则要经过本机网卡、网络交换设备和对方网卡。具体是否经 CPU 内存、走几级交换机由硬件拓扑及通信实现决定。跨数据中心 WAN 的带宽与延迟约束又不同，不能套用机内性能。

**RDMA** 是允许网络设备直接读写远端内存、减少远端 CPU 介入的通信机制；**GPUDirect RDMA** 在受支持的配置中使网卡能直接访问 GPU 内存，避免传统路径中不必要的主机内存中转，但仍需网络传输，不会消除同步等待。**NCCL** 则是软件库，选择并执行适合当前设备和网络的 GPU 集体通信，不是一种物理网线。

## 环形、树形和分层到底指什么

以 AllReduce 为例，**Ring（环形）**让进程沿环传递片段，适合利用带宽但要经过多轮交换；**Tree（树形）**先沿树汇总再分发，可减少某些场景的通信轮数。**Hierarchical Collective（分层集体通信）**把同节点 GPU 和跨节点 GPU 分组，先利用节点内互连，再跨节点通信，最后视操作需要在节点内分发。实际算法由实现与消息大小、拓扑决定，不能说某一种永远最快。
