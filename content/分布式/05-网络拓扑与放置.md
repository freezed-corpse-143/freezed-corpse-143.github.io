# 网络拓扑与放置：把逻辑分组放到物理机器上

[返回总览](./分布式大模型.md)

## 先看路径，再放进程

**逻辑拓扑**指 TP、PP、DP 等进程如何分组；**物理拓扑**指 GPU、NVLink/NVSwitch、PCIe、网卡及交换机如何连接。节点内和跨节点路径的带宽、延迟通常不同，不能假定 GPU 0 到 GPU 1 与 GPU 0 到 GPU 100 一样快。

示例：两台机器各有四张 GPU，共八张 GPU。若选择 TP=4、DP=2，可让每台机器的四张 GPU 组成一个 TP 组，再让两台机器构成两个 DP 副本。TP 同一层频繁交换数据，留在节点内通常更合适；DP 每步同步的通信则要经过跨节点网络。

这个例子不是硬规则：若节点内没有高速 GPU 互连，或者 PP 的激活传输远多于预期，应按实际消息大小、调用频次和硬件连接重新评估。PP 跨节点发送层间激活；EP 的专家分散到多个节点时也会触发跨节点 All-to-All。

**放置问题的核心**：哪组进程交换最频繁、每次发多少、实际经过什么链路？对照通信耗时测量，而不是仅凭“TP 一定在节点内”这样的口诀。

## 调度器怎样使用这张地图

**调度（scheduling）**决定作业何时运行、获得哪些机器；**放置（placement）**进一步决定每个并行组落在哪些 GPU。决策要同时检查显存是否够、软件环境是否兼容、同组设备速度是否接近，以及 TP/PP/DP/EP 各自实际产生的通信量。

仍以两台各四卡的机器为例：把 TP=4 的两个组分别放在同一台机器，可减少频繁的层内跨节点通信；两个 DP 副本同步梯度仍要走节点间网卡，因此节点间链路拥塞也会拉长 step。若改成 TP=8，单层计算能分给更多卡，却每层都可能跨节点交换结果；“卡多一倍”不保证更快。机架内、跨机架和跨数据中心的链路可能不同；先确认物理连接和通信频率，再决定放置。慢节点与负载不均的区别见[异构与慢节点](./04-异构与慢节点.md)。
