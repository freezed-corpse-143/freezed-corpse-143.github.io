# 显存与模型并行：模型为什么要拆

[返回总览](./分布式大模型.md)

## 先算一笔显存账

$P$ 个 BF16 参数仅权重约占 $2P$ 字节：1000 亿参数约为 200 GB（这里的 B 在“100B 参数”中指 billion，在“2 bytes”中指字节）。训练还要存梯度、优化器状态、前向激活和临时缓冲；不同精度、优化器和实现的占用不同，不能简单把 200 GB 当作训练总显存。推理一般无需梯度和优化器状态，却还要为请求保留 KV cache。

## 两种基本拆法

- **数据并行 DP**：每张卡各放一份完整模型，处理不同数据，再同步梯度。提升吞吐，但**不解决单卡放不下模型**的问题。
- **模型并行**：把模型计算或参数拆到多张卡，让每张卡只承担一部分；代价是卡之间必须通信。

常见模型并行方式：

| 方法       | 拆开的是什么     | 新手可以怎样想      | 主要代价                  |
| -------- | ---------- | ------------ | --------------------- |
| 张量并行 TP  | 一层内的矩阵计算   | 多卡合算同一层      | 层内频繁通信                |
| 流水线并行 PP | 连续的模型层     | 不同卡负责不同层     | 阶段间传激活，可能空等           |
| 上下文并行 CP | 长序列的上下文    | 多卡分担长序列计算与存储 | 注意力计算需要跨卡交换信息         |
| 序列并行 SP  | 某些算子的序列维激活 | 减少重复保存的激活    | 与 TP 配套时需额外通信         |
| 专家并行 EP  | MoE 中的专家网络 | 每卡持有部分专家     | token 路由产生 All-to-All |

**ZeRO / FSDP** 则在数据并行进程间分片参数、梯度和优化器状态；计算时按需聚合，节省常驻显存，付出通信和临时峰值显存。它们并非让所有算子天然能跨设备执行。实际训练常组合多种维度，但不是拆得越多越好：首先确认是权重、激活还是优化器状态撑爆显存，再选择对应拆法。

**例子**：一层权重单卡放不下，单用 DP 无效；TP 能拆这层，PP 能把不同层放到不同卡，ZeRO/FSDP 能减少每个数据并行进程持有的完整状态。它们解决的显存瓶颈不完全相同。
