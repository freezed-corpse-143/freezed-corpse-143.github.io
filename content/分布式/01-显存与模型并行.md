# 显存与模型并行：模型为什么要拆

[返回总览](./分布式大模型.md)

## 先算一笔显存账

$P$ 个 BF16 参数仅权重约占 $2P$ 字节：1000 亿参数约为 200 GB（这里的 B 在“100B 参数”中指 billion，在“2 bytes”中指字节）。训练还要存梯度、优化器状态、前向激活和临时缓冲；不同精度、优化器和实现的占用不同，不能简单把 200 GB 当作训练总显存。推理一般无需梯度和优化器状态，却还要为请求保留 KV cache。

## 两种基本拆法

- **数据并行 DP**：每张卡各放一份完整模型，处理不同数据，再同步梯度。提升吞吐，但**不解决单卡放不下模型**的问题。
- **模型并行**：把模型计算或参数拆到多张卡，让每张卡只承担一部分；代价是卡之间必须通信。

常见模型并行方式：

| 方法       | 拆开的是什么     | 新手可以怎样想      | 主要代价                  |
| -------- | ---------- | ------------ | --------------------- |
| 张量并行 TP  | 一层内的矩阵计算   | 多卡合算同一层      | 层内频繁通信                |
| 流水线并行 PP | 连续的模型层     | 不同卡负责不同层     | 阶段间传激活，可能空等           |
| 上下文并行 CP | 长序列的上下文    | 多卡分担长序列计算与存储 | 注意力计算需要跨卡交换信息         |
| 序列并行 SP  | 某些算子的序列维激活 | 减少重复保存的激活    | 与 TP 配套时需额外通信         |
| 专家并行 EP  | MoE 中的专家网络 | 每卡持有部分专家     | token 路由产生 All-to-All |

**ZeRO / FSDP** 则在数据并行进程间分片参数、梯度和优化器状态；计算时按需聚合，节省常驻显存，付出通信和临时峰值显存。它们并非让所有算子天然能跨设备执行。实际训练常组合多种维度，但不是拆得越多越好：首先确认是权重、激活还是优化器状态撑爆显存，再选择对应拆法。

**例子**：一层权重单卡放不下，单用 DP 无效；TP 能拆这层，PP 能把不同层放到不同卡，ZeRO/FSDP 能减少每个数据并行进程持有的完整状态。它们解决的显存瓶颈不完全相同。

## ZeRO-1 / 2 / 3：具体分片了什么

**ZeRO（Zero Redundancy Optimizer）**的出发点是：普通数据并行的每张卡都保存相同的模型参数、梯度和优化器状态；如果这些状态能在数据并行组里各存一部分，就不必重复占满每张卡的显存。假设有 4 个数据并行进程，下面的“四分之一”只表示理想化的**常驻状态份额**，不包含激活、通信缓冲或计算时临时聚合的峰值。

| 方案 | 优化器状态 | 梯度 | 参数 | 计算时要做什么 |
| --- | --- | --- | --- | --- |
| 普通 DP | 每卡完整 | 每卡完整 | 每卡完整 | 同步梯度 |
| ZeRO-1 | 每卡约 1/4 | 每卡完整 | 每卡完整 | 各进程更新自己负责的参数片段，再同步更新结果 |
| ZeRO-2 | 每卡约 1/4 | 每卡约 1/4 | 每卡完整 | 对梯度做分片归约，再同步更新后的参数 |
| ZeRO-3 | 每卡约 1/4 | 每卡约 1/4 | 每卡约 1/4 | 使用某层参数前按需聚合，用完释放/重新分片 |

这里的“优化器状态”以 Adam 为例，包括一阶、二阶动量，混合精度训练还可能有 FP32 主权重；**ZeRO-3 不是整次训练只需要四分之一参数显存**：计算层时仍可能暂时聚合完整的该层参数。阶段越高，常驻显存通常越少，但参数聚合和通信、临时峰值更值得关注。

**FSDP（Fully Sharded Data Parallel）**是 PyTorch 提供的完全分片数据并行技术/接口：跨数据并行进程分片参数、梯度和优化器状态，执行某个被 FSDP 包裹的模块时临时聚合参数，并在计算后重新分片。它在**分片目标上接近 ZeRO-3**，但不是“ZeRO-3 的另一个拼写”：实现、包裹粒度、预取与通信策略依具体配置而异。ZeRO 指分阶段消除数据并行冗余的方案；FSDP 指一种具体框架实现。普通 DP 的完整模型放不下时，参数分片可能帮上忙，但仍要检查单个模块聚合时的峰值显存。

## Pipeline Stage 与 Bubble：把层切成几段以后

**Pipeline stage（流水线阶段）**是一组连续模型层及负责计算它们的 GPU/进程，不是单独的一层，也不是一个训练 step。例如 12 层网络切给 3 个阶段：阶段 0 算第 1–4 层，阶段 1 算第 5–8 层，阶段 2 算第 9–12 层；阶段之间传递前向激活，反向时传递梯度。

若一次只送入一个大批次，阶段 0 算完后可能等反向梯度，其他阶段也会在启动或结束时空闲。把批次切成多个 **microbatch（微批次）**，便能在不同阶段同时处理不同微批次；但流水线填充和排空期间仍有 **bubble（空泡）**：某个阶段没有可执行的前向/反向任务而等待。微批次数更多通常有助于摊薄空泡，也会改变调度、激活存储和累积梯度的成本；不能把 bubble 当成网络故障。
