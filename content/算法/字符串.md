# 匹配问题

## 问题定义

给定一个**文本串** `T`（长度为 n）和一个**模式串** `P`（长度为 m），找出 `P` 在 `T` 中所有出现的位置。

```
T = "ABABABCABABABCABABABC"
P = "ABABC"
```

## 朴素算法

### 思路
从 `T` 的每个位置 `i` 开始，逐字符与 `P` 比较，若全部匹配则记录位置，否则从 `i+1` 重新开始。

### 代码
```python
def naive_search(T, P):
    n, m = len(T), len(P)
    res = []
    for i in range(n - m + 1):
        j = 0
        while j < m and T[i + j] == P[j]:
            j += 1
        if j == m:
            res.append(i)
    return res
```

### 复杂度
- 最坏：`O(n × m)`，例如 `T = "AAAAA...A"`，`P = "AAAB"`
- 最好：`O(n)`
- 空间：`O(1)`

### 问题
每次失配后，`i` 只前进一步，`j` 归零，**已经比较过的信息被浪费了**。


## KMP 算法（Knuth-Morris-Pratt）

### 关键概念：next 数组（前缀函数）
`next[j]` 表示 `P[0..j-1]` 的**最长相等前后缀长度**。

以 `P = "ABABC"` 为例：

| j    | 子串   | 最长相等前后缀 | next[j] |
| ---- | ------ | -------------- | ------- |
| 0    | ""     | 0              | -1      |
| 1    | "A"    | 0              | 0       |
| 2    | "AB"   | 0              | 0       |
| 3    | "ABA"  | "A"            | 1       |
| 4    | "ABAB" | "AB"           | 2       |

### 匹配过程
失配时 `j = next[j]`，而不是归零。

```python
def kmp_search(T, P):
    n, m = len(T), len(P)
    # 构建 next 数组
    nxt = [0] * m
    k = 0
    for i in range(1, m):
        while k > 0 and P[i] != P[k]:
            k = nxt[k - 1]
        if P[i] == P[k]:
            k += 1
        nxt[i] = k

    # 匹配
    res = []
    j = 0
    for i in range(n):
        while j > 0 and T[i] != P[j]:
            j = nxt[j - 1]
        if T[i] == P[j]:
            j += 1
        if j == m:
            res.append(i - m + 1)
            j = nxt[j - 1]
    return res
```

### 复杂度
- 时间：`O(n + m)`
- 空间：`O(m)`

### 直观理解
```
位置:  0 1 2 3 4 5 6 7
T:     A B A B A B A C
P:     A B A B A C
                   ↑ j=5 处失配
       0 1 2 3 4 5
```

于是 `j` 从 5 跳到 3，`i` 不回退

```
T:  A B A B A B A C
        A B A B A C
        ↑
        P[0] 对齐到 T[2]
```

## 核心思想

模式串在比较位置 `i` 的子串 `p[0..i]` ，

寻找一个尽可能大的相同的前缀和后缀匹配。

以 `P[0..3] = "ABAB"` 为例，它的最长相等真前后缀是 `"AB"`（长度 `k = 2）：

```
  0   1   2   3  
┌───┬───┬───┬───┐
│ A │ B │ A │ B │
└───┴───┴───┴───┘
前缀 k=2：
┌───┬───┐
│ A │ B │-> 扩展
└───┴───┘
后缀 k=2：
        ┌───┬───┐
        │ A │ B │-> 扩展
        └───┴───┘
```

### 如何递归计算

以 `P[0..3] = "ABABA"` 为例

```
  0   1   2   3   4
┌───┬───┬───┬───┬───┐
│ A │ B │ A │ B │ A │
└───┴───┴───┴───┴───┘
前缀 k=2：
┌───┬───┐
│ A │ B │-> 扩展
└───┴───┘
		┌───┐
		│ A │
		└───┘
后缀 k=2：
        ┌───┬───┐
        │ A │ B │-> 扩展
        └───┴───┘
        		┌───┐
				│ A │
				└───┘
因为 p[2] == p[4]
所以 next[4] = next[3]+1
```

接收后

```
  0   1   2   3   4
┌───┬───┬───┬───┬───┐
│ A │ B │ A │ B │ A │
└───┴───┴───┴───┴───┘
前缀 k=3：
┌───┬───┬───┐
│ A │ B │ A │-> 扩展
└───┴───┴───┘
后缀 k=3：
        ┌───┬───┬───┐
        │ A │ B │ A │-> 扩展
        └───┴───┴───┘
```

# Z 算法（扩展 KMP）

## 设定

```
原串（文本）T = "ABAB"      长度 n = 4
T: ┌───┬───┬───┬───┐
   │ A │ B │ A │ B │
   └───┴───┴───┴───┘
     0   1   2   3
模式串       P = "AB"       长度 m = 2
P: ┌───┬───┐
   │ A │ B │
   └───┴───┘
```

## 构造新串

```
S = P + "#" + T
  = "AB" + "#" + "ABAB"
  = "AB#ABAB"
```

```
S: ┌───┬───┬───┬───┬───┬───┬───┐
   │ A │ B │ # │ A │ B │ A │ B │
   └───┴───┴───┴───┴───┴───┴───┘
     0   1   2   3   4   5   6
```

- 位置 0~1：模式串 P
- 位置 2：分隔符 `#`（防止匹配跨越 P 和 T 的边界）
- 位置 3~6：原文本 T

`Z[i]`：表示从 `S[i]` 开始往后数，能和 `S` 开头的连续对上多少个字符。

**为什么要加 `#`？**
因为如果不加，`Z[i]` 可能跨越 P 和 T 的边界，得到一个"虚假的匹配"。`#` 和任何字符都不等，一旦比到 `#` 就会停下。

参考 next 数组算法

```
  0   1   2   3   4   5   6
┌───┬───┬───┬───┬───┬───┬───┐
│ A │ B │ # │ A │ B │ A │ B │
└───┴───┴───┴───┴───┴───┴───┘
┌───┬───┐
│ A │ B │
└───┴───┘
			┌───┬───┐
			│ A │ B │
			└───┴───┘
					┌───┬───┐
					│ A │ B │
					└───┴───┘
```

## Z-box 的加速

```
  0   1   2   3   4   5   6
┌───┬───┬───┬───┬───┬───┬───┐
│ A │ B │ # │ A │ B │ A │ B │
└───┴───┴───┴───┴───┴───┴───┘
  0   1   2   3   4   5   6
		    ┌───────┐
		    │ box   │      ← [l=3, r=5)
		    └───────┘
                 
   这段 S[3..4] == S[0..1]
```

**关键**：box 内的**每一个位置**，都可以直接借用"镜像位置"的答案，不需要从头比。

`Z[0..1]` 是类似 next 数组的功能。从左到右计算的。

当运算到 `Z[4]`，由于 `S[0..1]==S[3..4]`，`Z[4] == Z[1]`。

# Boyer-Moore 算法

Boyer-Moore（简称 BM）是**实际应用中最快的字符串匹配算法**之一，也是许多文本编辑器（如 GNU grep）的默认算法。它的核心思想非常反直觉：

> **从右向左比较，失配时跳跃式移动，而不是一格一格挪。**

## 一、先看朴素算法为什么慢

```
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
P: ┌───┬───┬───┐
   │ A │ N │ D │
   └───┴───┴───┘

朴素：从 T 的每个位置开始，从左往右逐字符比
     比一次挪一格，最坏 O(n×m)
```

而 BM 的做法是：

```
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
P:         ┌───┬───┬───┐
           │ A │ N │ D │
           └───┴───┴───┘
             ↑ 从右往左比：先比 D 和 E
             
   'D' ≠ 'E'，且 'E' 不在 P 中
   → P 可以一次跳过整个长度，右移 3 格！
```

**一次跳跃，跳过 3 格**，这就是 BM 快的原因。

## 二、BM 的两条规则

BM 用两个独立的启发式规则决定"失配时 P 右移多少"，取**较大者**。

```
┌─────────────────────────────────────────────┐
│  坏字符规则（Bad Character）                │
│  好后缀规则（Good Suffix）                  │
│                                             │
│  实际移动距离 = max(坏字符建议, 好后缀建议) │
└─────────────────────────────────────────────┘
```

---
## 坏字符规则（Bad Character Rule）

### 核心思想

比较时**从右往左**。当 `T[i]` 和 `P[j]` 失配时，`T[i]` 就是"坏字符"。

看这个坏字符在 `P` 中**最右出现的位置**：

- 如果它在 `P` 中出现过 → 把 P 右移，让 P 中那个字符对齐到 `T[i]`
- 如果它没在 `P` 中出现过 → 直接把 P 跳过整个坏字符位置

### 图示

```
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
     0   1   2   3   4   5   6   7

P: ┌───┬───┬───┐
   │ A │ N │ D │
   └───┴───┴───┘
     0   1   2

对齐 T[0..2]：
  T[2]='R' vs P[2]='D' → 失配
  坏字符 = 'R'

'R' 在 P 中吗？ 不在！
→ P 直接右移，跳过这个位置
```

**移动量计算**：

```
移动量 = j - (坏字符在 P 中最右出现的位置)
       = j - (-1)   （没出现就用 -1）
       = j + 1
```

这里 `j = 2`（失配位置），`'R'` 不在 P 中，`last['R'] = -1`：

```
移动量 = 2 - (-1) = 3
```

右移 3 格后：

```
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
               ┌───┬───┬───┐
               │ A │ N │ D │
               └───┴───┴───┘
               比较 T[5]='S' vs P[2]='D' → 失配
               'S' 也不在 P 中 → 再跳 3
```

### 另一个例子：坏字符在 P 中出现过

```
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
	 0   1   2   3   4   5   6   7
P: ┌───┬───┬───┐
   │ E │ R │ D │
   └───┴───┴───┘
     0   1   2

从右往左：
  T[2]='R' vs P[2]='D' → 失配
  坏字符 = 'R'
'R' 在 P 中吗？
  P[1] = 'R'  → 在！最右出现位置 = 1
```

坏字符规则计算：

```
移动量 = j - bad_char['R']
       = 2 - 1
       = 1
```

**解释**：坏字符 `'R'` 在 P 的位置 1 出现过，把 P 右移 1 格，让 `P[1]='R'` 对齐到 `T[2]='R'`。

```
移动前：
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
     0   1   2   3   4   5   6   7
P: ┌───┬───┬───┐
   │ E │ R │ D │
   └───┴───┴───┘
     0   1   2
             ↑ D 和 R 失配
             
移动后（右移 1 格）：
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ H │ E │ R │ E │ I │ S │ A │ N │
   └───┴───┴───┴───┴───┴───┴───┴───┘
     0   1   2   3   4   5   6   7
       ┌───┬───┬───┐
P:     │ E │ R │ D │
       └───┴───┴───┘
         0   1   2
                 ↑
          现在 P[1]='R' 对齐到 T[2]='R' ✓
```

**关键对比**：
- 如果坏字符**不在 P 中**（比如 `'X'`），移动量 = `2 - (-1) = 3`，跳 3 格
- 如果坏字符**在 P 中**（这里是 `'R'`），移动量 = `2 - 1 = 1`，只跳 1 格

**坏字符在 P 中出现时，跳跃幅度变小了**——因为要"迁就"那个已经出现过的位置。
继续下一轮，比较 `T[3]` 与 `P[2]`

## 好后缀规则（Good Suffix Rule）

### 核心思想

从右往左比，失配前**已经匹配的那一段**叫"好后缀"。

即使坏字符规则失效（比如坏字符就在当前位置右边出现过），好后缀规则还能提供跳跃。

### 图示

```
T: ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ A │ B │ X │ A │ B │ C │ A │ B │
   └───┴───┴───┴───┴───┴───┴───┴───┘
     0   1   2   3   4   5   6   7

P: ┌───┬───┬───┬───┬───┐
   │ A │ B │ C │ A │ B │
   └───┴───┴───┴───┴───┘
     0   1   2   3   4
     
从右往左比： 
T[4]='B' vs P[4]='B'  ✓
T[3]='A' vs P[3]='A'  ✓
T[2]='X' vs P[2]='C'  ✗   ← 失配
```

此时：

```
失配位置 j = 2
坏字符 = T[2] = 'X'
好后缀 = P[3..4] = "AB"  （已匹配的那段）
```
