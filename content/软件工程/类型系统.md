
# Primitive / Composite Type（原始类型 / 符合类型）

**原始类型（Primitive）**：语言内置、不可再分的基本类型。
- 例：`Int`、`Float`、`Bool`、`Char`、`String`（某些语言里 String 是复合的）

**复合类型（Composite）**：由其他类型组合而成的类型。
- 例：数组 `[Int]`、元组 `(Int, String)`、结构体 `struct Point { x: Int, y: Int }`

> 区别核心：是否由其他类型“构造”出来。

# Product Type (积类型)

**定义**：一个类型的值同时包含多个字段，字段数量是“笛卡尔积”关系。

- 例：`(A, B)`、`struct { a: A, b: B }`
- 可能的值数量 = `|A| × |B|`

**直观理解**：”A 和 B 同时都有“。


# Sum Type（和类型）

**定义**：一个类型的值只能是若干变体中的一种。

- 例：`A | B`、`enum { Left(A), Right(B) }`
- 可能的值数量 = `|A| + |B|`

**直观理解**：”A 或 B，二选一“。

# Algebraic Data Types（代数数据类型，ADT）

**定义**：由 Product 和 Sum 组合而成的类型系统。

- 名字来源：类型可以像代数一样运算（× 表示积，+ 表示和）
- 例（Haskell）：
```haskell
data Shape = Circle Float | Rectangle Float Float
```
  这是 Sum of Products。

**意义**：用少量原语构造出丰富的数据结构，且能保证穷尽性。

# Enum / Tagged Union（枚举 / 带标签联合）

**Enum**：一组命名的常量。
- 例：`enum Color { Red, Green, Blue }`

**Tagged Union**：每个变体带标签，且可携带数据。
- 例（Rust）：
  ```rust
  enum Message {
      Quit,
      Move { x: i32, y: i32 },
      Write(String),
  }
  ```
- 也叫： discriminated union、variant、sum type 的实现形式。

> Enum 是 Tagged Union 的简化版（无数据）。

# Pattern Matching（模式匹配）

**定义**：根据值的结构进行分支判断并解构。

- 例（Rust）：
  ```rust
  match msg {
      Message::Quit => ...,
      Message::Move { x, y } => ...,
      Message::Write(s) => ...,
  }
  ```
- 特点：编译器可检查是否穷尽所有情况（exhaustiveness check）

**意义**：与 Sum Type 搭配，安全地解构数据。

# Generic（泛型）

**定义**：类型作为参数，使代码可复用于多种类型。

- 例：`List<T>`、`fn identity<T>(x: T) -> T`
- 目的：类型安全 + 代码复用，避免强制类型转换。

# Generic Constraint（泛型约束）

**定义**：限制泛型参数必须满足某些条件。

- 例（Rust）：`fn print<T: Display>(x: T)`
- 例（Java）：`<T extends Comparable<T>>`
- 目的：在泛型体内能调用特定方法。

# Trait / Typeclass（特征 / 类型类）

**Trait（Rust）**：定义一组方法签名，类型可实现它。
```rust
trait Speak { fn speak(&self) -> String; }
```

**Typeclass（Haskell）**：类似接口，但支持更灵活的分派。
```haskell
class Speak a where speak :: a -> String
```

**意义**：抽象行为，实现多态（ad-hoc polymorphism）。

# Associated Type（关联类型）

**定义**：Trait 中定义的占位类型，由实现者指定。

- 例（Rust）：
  ```rust
  trait Container {
      type Item;
      fn get(&self, i: usize) -> Self::Item;
  }
  ```
- 对比泛型参数：关联类型每个实现只能有一个，泛型参数可以有多个。

**意义**：让 Trait 更清晰，避免类型参数爆炸。

# Newtype（新类型）

**定义**：把已有类型包一层，形成全新的类型。

- 例（Rust）：`struct Meters(f64);`
- 例（Haskell）：`newtype UserId = UserId Int`

**意义**：
- 类型安全（`Meters` 和 `Seconds` 不混用）
- 零运行时开销（通常编译期擦除）
- 可为其实现 trait，而不影响原类型

# Phantom Type (幽灵类型)

**定义**：类型参数在运行时不存在，仅用于编译期标记。

- 例（Rust）：
  ```rust
  struct Length<Unit> { value: f64, _marker: PhantomData<Unit> }
  ```
- `Unit` 不占空间，但能区分 `Length<Meters>` 和 `Length<Feet>`

**意义**：编译期状态标记、单位区分、类型安全。

# Option / Maybe

**定义**：表示“可能有值，也可能没有”。

- Rust：`Option<T> = Some(T) | None`
- Haskell：`Maybe a = Just a | Nothing`

**意义**：用类型系统表达“缺失”，替代 null。

# Result / Either

**定义**：表示“成功或失败”。

- Rust：`Result<T, E> = Ok(T) | Err(E)`
- Haskell：`Either e a = Left e | Right a`

**意义**：显式处理错误，避免异常穿透。

# Null Safety（空安全）

**定义**：类型系统区分“可为空”和“不可为空”。

- Kotlin：`String` vs `String?`
- Swift：`String` vs `String?`
- Rust：没有 null，用 `Option`

**意义**：编译期消除空指针异常。

# Variance (型变)

**定义**：当 `A` 是 `B` 的子类型时，`Container<A>` 和 `Container<B>` 的关系。

| 型变               | 关系             | 例子         |
| ---------------- | -------------- | ---------- |
| 协变 Covariant     | `F<A> <: F<B>` | 只读容器、函数返回值 |
| 逆变 Contravariant | `F<B> <: F<A>` | 函数参数       |
| 不变 Invariant     | 无关系            | 可变容器       |

**意义**：保证类型安全的同时允许灵活替换。

# Subtyping（子类型）

**定义**：若 `A` 可被当作 `B` 使用，则 `A <: B`。

- 例：`Cat <: Animal`
- 形式：名义子类型（Java 继承）、结构子类型（TypeScript）

**意义**：多态的基础。

# Type State（类型状态）

**定义**：用类型参数编码对象的状态，使非法状态无法编译。

- 例：
  ```rust
  struct Door<State> { ... }
  struct Open;
  struct Closed;
  impl Door<Closed> { fn open(self) -> Door<Open> {...} }
  impl Door<Open> { fn close(self) -> Door<Closed> {...} }
  ```
- 无法在 `Closed` 状态调用 `close`，编译期报错。

**意义**：把状态机提升到类型层，消除运行时状态错误。

# 总结图谱

```
类型系统
├── 基础：Primitive / Composite
├── 构造：Product + Sum = ADT
│         └── Enum / Tagged Union
│         └── Pattern Matching（消费 ADT）
├── 抽象：Generic → Generic Constraint
│         └── Trait / Typeclass → Associated Type
│         └── Newtype / Phantom Type
├── 错误：Option / Result → Null Safety
├── 关系：Variance / Subtyping
└── 进阶：Type State
```

**核心思想**：把越来越多的正确性约束从运行时前移到编译期——这是现代类型系统演进的主线。
