# 底层原语（OS / 硬件级）

这些是其他一切抽象的地基。

| 概念            | 作用            | 关键点                                             |
| ------------- | ------------- | ----------------------------------------------- |
| **Thread**    | 操作系统调度的最小执行单元 | 共享同一地址空间；切换开销大；数量受限于内存栈                         |
| **Mutex**     | 互斥锁，保护临界区     | 保证同一时刻只有一个线程进入；会阻塞；可能死锁                         |
| **Semaphore** | 计数信号量         | 控制"同时访问某资源的数量"；Mutex 是它的特例（=1）                  |
| **Atomic**    | 原子操作          | 无锁；CPU 指令级保证（CAS、fetch-add）；是 Lock-free 数据结构的基础 |

**核心问题**：这些原语直接组合极易出错（死锁、竞态、优先级反转）。于是有了更高层抽象。

# Future / Promise 

表示**"一个尚未完成、但将来会有结果的值"**。

- **Promise**：写入端（生产者）——你承诺将来给它一个值。
- **Future**：读取端（消费者）——你拿着它等将来的值。

不同语言叫法混乱（Java 的 `Future`、JS 的 `Promise`、Rust 的 `Future`），本质是同一个"占位符"思想。
# Async / Await

让**异步代码看起来像同步代码**的语法糖。

```
Task
 ↓ await   ← 挂起当前任务，让出执行权，不阻塞线程
Task
 ↓ await
Task
```

关键理解：
- `await` 不是"阻塞等待"，而是**"挂起 + 注册回调 + 让出线程"**。
- 底层由 **Event Loop** 或 **Runtime 调度器** 驱动。
- 适合 **I/O 密集**场景（一个线程可挂起成千上万个任务）。
- **不解决 CPU 并行问题**——CPU 密集仍需多线程。

# Coroutine（协程）

**用户态的可挂起函数**。线程由 OS 调度，协程由语言 Runtime 调度。

- 比线程轻量（KB 级 vs MB 级栈）
- 切换不经过内核
- `async/await` 通常是协程的一种语法形式
- Go 的 goroutine、Kotlin 的 coroutine、Python 的 asyncio 都属于此类

**协程 ≠ 并发模型**，它是一种**实现并发的手段**，可以承载下面任何一种模型。

# Shared Memory（共享内存）

```
Thread A ─┐
          ├── Shared State
Thread B ─┘
```

- **通信方式**：读写同一块内存
- **同步手段**：Mutex、Semaphore、Atomic
- **优点**：性能高、直观
- **缺点**：数据竞争、死锁、调试地狱
- **代表**：C/C++ pthread、Java 线程
- **哲学**：**"别通过通信共享内存，而要通过共享内存通信"** 的反面

# Message Passing / Actor

```
Actor A ─message→ Actor B
```

- **通信方式**：只发消息，不共享状态
- **每个 Actor**：有自己的私有状态 + 一个邮箱（Mailbox）
- **处理消息**：串行处理，天然无锁
- **优点**：无数据竞争、易分布式
- **缺点**：消息延迟、邮箱溢出、调试消息流困难
- **代表**：Erlang/Elixir、Akka（JVM）、Actix（Rust）

# CSP（Communicating Sequential Processes）

```
Task A ─Channel→ Task B
```

- **通信方式**：通过 **Channel** 传递数据
- **和 Actor 的区别**：
  - Actor 消息是**发给某个 Actor**（有身份）
  - CSP 是**通过 Channel 传递**（Channel 是匿名管道，谁在两端不确定）
  - Actor 通常异步；CSP 的 Channel 常可同步阻塞（会合点）
- **优点**：结构清晰、天然同步点
- **代表**：**Go 的 goroutine + channel**（最典型）、Clojure core.async

> Go 名言：**"Do not communicate by sharing memory; instead, share memory by communicating."**

# Async / Await（异步事件驱动）

```
Task
 ↓ await
Task
 ↓ await
Task
```

- **通信方式**：通常靠 Future 组合 + 回调
- **驱动**：Event Loop（单线程）或多线程 Runtime
- **优点**：单线程高并发 I/O、无锁
- **缺点**：函数"染色"（async 传染）、调试栈复杂、CPU 密集无优势
- **代表**：JavaScript、Python asyncio、Rust tokio

# 对比表

| 维度       | Shared Memory | Actor       | CSP     | Async/Await |
| ---------- | ------------- | ----------- | ------- | ----------- |
| 通信       | 共享变量      | 消息        | Channel | Future 组合 |
| 同步       | Mutex/Atomic  | 邮箱        | Channel | await       |
| 竞争风险   | 高            | 无          | 无      | 无          |
| 分布式友好 | 差            | 极好        | 中      | 中          |
| 代表       | C++/Java      | Erlang/Akka | Go      | JS/Rust     |
| 调度       | OS            | Runtime     | Runtime | Event Loop  |

# Channel

CSP 的核心载体，Go 里最常见：

```go
ch := make(chan int)

go func() { ch <- 42 }()   // 发送
v := <-ch                   // 接收
```

- **无缓冲 Channel**：发送和接收必须**同时就绪**（会合 rendezvous）
- **有缓冲 Channel**：缓冲区未满可发，未空可收
- 是**线程安全**的，天然替代 Mutex 做很多同步工作
- 可关闭、可 `select` 多路复用

# Event Loop (事件循环)

单线程（或每线程一个）循环：

```
while true:
    events = poll_events()
    for e in events:
        dispatch(e)   // 执行回调 / 恢复协程
```

- Node.js、浏览器 JS、Python asyncio、Redis 都用它
- **所有任务在同一个线程上交替执行**，所以不需要锁
- 前提：任务必须**短且非阻塞**（否则整个循环卡死）

# Structured Concurrency（结构化并发）

**这是近年最重要的范式演进**，目的是解决"协程/线程泄漏"问题。

##=# 核心原则
> **并发任务的生命周期，必须被词法作用域严格约束。**

就像 `if` / `for` 有明确的作用域，**并发块也必须有**：

```
scope {
    spawn task A
    spawn task B
}   // ← 到这里，A 和 B 必须都已结束
```

## 它解决什么？

传统写法：
```python
t = Thread(target=work)
t.start()
# 忘了 join → 线程泄漏；异常无人管
```

结构化写法（Python 3.11+ `TaskGroup`、Kotlin `coroutineScope`、Java 21 `StructuredTaskScope`）：

```python
async with asyncio.TaskGroup() as tg:
    tg.create_task(A())
    tg.create_task(B())
# 离开块时：两个任务都结束
# 任一失败 → 其余自动取消 → 异常向上传播
```

## 三大保证
1. **不泄漏**：作用域结束 = 所有子任务结束
2. **异常传播**：子任务异常不会静默丢失，会聚合上报
3. **取消传播**：父任务取消 → 所有子任务自动取消

## 为什么重要？
它把**并发**从"裸的、无序的、易泄漏的"变成**像控制流一样可组合、可推理**的。是 Go 的 `errgroup`、Kotlin 的 `coroutineScope`、Python `TaskGroup`、Swift `TaskGroup` 共同的方向。
