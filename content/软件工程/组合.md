# Composition

装饰器本质是：

> 包一层，不改原对象，增加行为。

```python
def log(func):
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)
        print("after")
        return result
    return wrapper
```

结构是：

```text
wrapper -> func
```

这就是组合。

装饰器模式不要求修改 `func`，而是让 `wrapper` 持有 `func`，在调用前后加逻辑。

# Adapter

适配器本质是：

> 把一个接口转换成另一个接口。

```python
class OldPrinter:
    def old_print(self, text):
        print(text)

class PrinterAdapter:
    def __init__(self, old_printer):
        self.old_printer = old_printer

    def print(self, text):
        self.old_printer.old_print(text)
```

结构是：

```text
Adapter -> OldPrinter
```

它没有继承旧类，而是组合旧对象，然后暴露新接口。

# Middleware

中间件本质是：

> 在请求处理前后插入一层逻辑，并决定是否继续传递。

```python
def auth_middleware(next_handler):
    def handler(request):
        if not request.user:
            return "401"
        return next_handler(request)
    return handler
```

结构是：

```text
middleware -> next_handler
```

多个中间件会形成：

```text
A -> B -> C -> 业务逻辑
```

这就是组合链。

# Pipeline

管道本质是：

> 把多个处理步骤按顺序组合起来。

```python
result = data
for step in steps:
    result = step(result)
```

或者：

```text
input -> step1 -> step2 -> step3 -> output
```

每个 step 只关心自己的输入输出，整体通过组合形成复杂流程。

# Plugin

插件本质是：

> 主程序定义扩展点，插件通过组合挂载进去。

```python
class App:
    def __init__(self):
        self.plugins = []

    def register(self, plugin):
        self.plugins.append(plugin)

    def run(self):
        for plugin in self.plugins:
            plugin.apply(self)
```

结构是：

```text
App has plugins
```

插件不是继承主程序，而是被主程序组合进来。

# Capability

Capability 本质是：

> 一个对象拥有某些能力，不一定靠继承，而是靠组合能力模块。

```python
class FileReader:
    ...

class FileWriter:
    ...

class FileService:
    def __init__(self):
        self.reader = FileReader()
        self.writer = FileWriter()
```

`FileService` 的能力来自它组合了 `reader` 和 `writer`。

类似：

```text
对象 = 基础对象 + 多个 capability
```

# Mixin

Mixin 看起来像继承，但通常也是组合思想。

```python
class LogMixin:
    def log(self, msg):
        print(msg)

class Service(LogMixin):
    pass
```

Mixin 的目的是：

> 把一组可复用行为混入类中。

虽然语法上是继承，但设计意图接近组合：不是表达“Service 是一种 LogMixin”，而是“Service 获得了 log 能力”。

现代语言更倾向于用组合替代 Mixin。

# Extension

Extension 本质是：

> 在不修改原对象的情况下，给它增加额外行为。

比如浏览器扩展：

```text
Browser + Extension
```

或者代码里：

```python
class User:
    pass

def with_age(user, age):
    user.age = age
    return user
```

扩展通常也是组合：

```text
原对象 + 扩展逻辑
```

# 共同结构

这些概念大多可以抽象成：

```text
Client -> Wrapper/Chain/Container -> Core
```

或者：

```text
Base + Addon1 + Addon2 + Addon3
```

核心思想都是：

1. 不修改原对象
2. 通过持有、包装、串联、注册来扩展
3. 每个部分职责单一
4. 整体行为由组合产生

# 走向 Composition

因为继承有几个问题：

- 父类变化会影响子类
- 多层继承难以理解
- 无法运行时动态替换
- 容易产生庞大基类
- 职责容易纠缠

组合更灵活：

```text
继承：编译期固定，强耦合
组合：运行期可变，弱耦合
```

所以很多现代设计原则会说：

> Favor composition over inheritance.
