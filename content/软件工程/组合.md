# Composition

装饰器本质是：

> 包一层，不改原对象，增加行为。

```python
def log(func):
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)
        print("after")
        return result
    return wrapper
```

结构是：

```text
wrapper -> func
```

这就是组合。

装饰器模式不要求修改 `func`，而是让 `wrapper` 持有 `func`，在调用前后加逻辑。

# Adapter

适配器本质是：

> 把一个接口转换成另一个接口。

```python
class OldPrinter:
    def old_print(self, text):
        print(text)

class PrinterAdapter:
    def __init__(self, old_printer):
        self.old_printer = old_printer

    def print(self, text):
        self.old_printer.old_print(text)
```

结构是：

```text
Adapter -> OldPrinter
```

它没有继承旧类，而是组合旧对象，然后暴露新接口。

# Middleware

中间件本质是：

> 在请求处理前后插入一层逻辑，并决定是否继续传递。

```python
def auth_middleware(next_handler):
    def handler(request):
        if not request.user:
            return "401"
        return next_handler(request)
    return handler
```

结构是：

```text
middleware -> next_handler
```

多个中间件会形成：

```text
A -> B -> C -> 业务逻辑
```

这就是组合链。

# Pipeline

管道本质是：

> 把多个处理步骤按顺序组合起来。

```python
result = data
for step in steps:
    result = step(result)
```

或者：

```text
input -> step1 -> step2 -> step3 -> output
```

每个 step 只关心自己的输入输出，整体通过组合形成复杂流程。

# Plugin

插件本质是：

> 主程序定义扩展点，插件通过组合挂载进去。

```python
class App:
    def __init__(self):
        self.plugins = []

    def register(self, plugin):
        self.plugins.append(plugin)

    def run(self):
        for plugin in self.plugins:
            plugin.apply(self)
```

结构是：

```text
App has plugins
```

插件不是继承主程序，而是被主程序组合进来。
