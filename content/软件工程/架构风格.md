# Modular Monolith（模块化单体）

**一句话**：一个进程、一次部署，但内部被严格划分为高内聚、低耦合的模块。

- **特点**：单一代码库、单一部署单元；模块之间通过明确的接口通信，不允许随意跨模块访问数据库表。
- **优点**：部署简单、调试容易、事务天然一致；比"大泥球"单体更易维护。
- **缺点**：无法按模块独立扩缩容；模块边界靠纪律维持，容易退化。
- **适用**：中小团队、业务尚未稳定、想保留未来拆分为微服务的可能性。

> 常被视为「微服务的务实替代品」——先做好模块边界，需要时再拆。

# Microkernel（微内核架构）

**一句话**：核心系统只提供最小功能，其余能力通过插件挂载。

- **结构**：`Core System`（核心，稳定）+ `Plug-ins`（可变部分）。
- **特点**：核心负责插件注册、生命周期、通信；插件独立开发、独立部署。
- **优点**：可扩展性极强、易定制、核心稳定。
- **缺点**：核心设计难度高，插件间通信和版本兼容复杂。
- **典型**：Eclipse、VS Code、Chrome、操作系统内核、规则引擎。

> 微内核是"架构风格"，Plugin Architecture 是它在实践中的常见落地形态。

# Plugin Architecture（插件架构）

**一句话**：宿主程序定义扩展点，第三方或内部团队实现插件来增强功能。

- **机制**：扩展点（Extension Point）+ 契约接口 + 注册/发现机制。
- **与微内核关系**：几乎可以视为同义词；微内核更强调"核心极小"，插件架构更强调"扩展机制"。
- **优点**：功能可热插拔、生态可生长、发布解耦。
- **缺点**：接口一旦发布难改；插件质量与安全难控。
- **典型**：Webpack、Babel、Figma 插件、浏览器扩展。

# Event Driven (事件驱动架构，EDA)

**一句话**：组件之间不直接调用，而是通过"发布/订阅事件"来协作。

- **结构**：生产者 → 事件总线/ broker → 消费者。
- **模式**：
  - **Pub/Sub**：事件广播，多个消费者各自处理。
  - **Event Streaming**：事件持久化、可回放（Kafka）。
  - **Event Sourcing**：状态由事件序列推导。
- **优点**：极致解耦、异步、高吞吐、易扩展。
- **缺点**：最终一致性、调试困难、事件顺序与幂等性挑战。
- **典型**：Kafka、RabbitMQ、订单→库存→通知链路。

# Microservices（微服务）

**一句话**：把系统拆成一组小型、独立部署、围绕业务能力组织的服务。

- **特点**：独立进程、独立数据库、HTTP/gRPC/消息通信、独立团队负责。
- **优点**：独立部署与扩缩容、技术异构、团队自治。
- **缺点**：分布式复杂度（网络、事务、可观测性）、运维成本高。
- **对比**：与 Modular Monolith 是"分布式 vs 进程内"的取舍；与 EDA 常结合使用（服务间异步事件）。

# Serverless（无服务器）

**一句话**：开发者只写函数/业务逻辑，基础设施与扩缩容完全交给平台。

- **形态**：
  - **FaaS**：AWS Lambda、Cloud Functions（按调用计费）。
  - **BaaS**：托管数据库、认证、存储等。
- **优点**：零运维、按用量付费、自动弹性到 0。
- **缺点**：冷启动、执行时长限制、厂商锁定、本地调试难。
- **本质**：是**部署与运维模型**，可与微服务、EDA 组合（事件触发函数）。

# Data-oriented Architecture（面向数据的架构）

> 注意：这个词有歧义，常见两种含义。

**A. 数据为中心的企业架构**
- 以数据资产为核心，服务围绕数据产品组织。
- 相关概念：Data Mesh、Data Fabric、Lakehouse。
- 特点：数据作为一等公民，跨系统共享、治理、血缘清晰。

**B. 面向数据编程（Data-Oriented Design, DOD）**
- 源自游戏/高性能计算：按内存布局组织数据（SoA），而非按对象（OOP）。
- 关注 CPU 缓存友好、批量处理，而非继承多态。

在**架构分类**语境下，通常指 **A**：以数据流和数据所有权来划分系统边界，而非以功能或 UI 划分。

# 横向对比

| 架构                 | 拆分粒度          | 通信方式      | 部署单元    | 核心诉求      |
| -------------------- | ----------------- | ------------- | ----------- | ------------- |
| Modular Monolith     | 模块              | 进程内调用    | 1 个        | 简单 + 可维护 |
| Microkernel / Plugin | 核心 + 插件       | 扩展点接口    | 核心 + 插件 | 可扩展        |
| Event Driven         | 事件生产者/消费者 | 事件/消息     | 多          | 解耦 + 异步   |
| Microservices        | 服务              | 网络 API/消息 | 多          | 独立部署      |
| Serverless           | 函数              | 事件/HTTP     | 平台托管    | 零运维        |
| Data-oriented        | 数据域/产品       | 数据流        | 视实现      | 数据治理      |
# 关系与组合

- **Modular Monolith → Microservices**：常见的演进路径。
- **Microkernel = Plugin Architecture** 的理论化表达。
- **Microservices + Event Driven**：最主流的现代组合。
- **Serverless** 常作为微服务/EDA 的部署载体。
- **Data-oriented** 是横切视角，可与上面任意一种共存。
