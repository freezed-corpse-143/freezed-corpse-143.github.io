# 图片分割调研：从描摹到区域拆分与图层分解

> 调研日期：2026-11-07。依据项目 README、官方文档与 Hugging Face 模型卡整理；未安装运行下列工具，也未对示例图片做效果对比。操作路径来自文档，具体菜单、依赖与在线演示状态可能随版本变化。

## 一、分割目标：先确定“可拆分对象”是什么

把一张图片变成可编辑对象，并不只有“描摹”这一种技术。应先明确需要编辑的是轮廓、像素区域、语义部件，还是完整的图层结构。

| 目标 | 希望得到什么 | 对应技术 | 常见输出 |
| --- | --- | --- | --- |
| 改颜色、改轮廓、放大不出现像素锯齿 | 由节点和曲线组成的形状 | 图像描摹／矢量化 | SVG、矢量路径 |
| 沿黑色描边拆开各个封闭区域 | 区域编号、选区或独立色块 | 线稿区域分割 | 标签图、Mask、透明 PNG |
| 没有描边时按色块边界拆分 | 按颜色及空间关系划分的区域 | 颜色聚类、连通域、分水岭等 | 区域图、分层 PSD |
| 单独取出头发、蝴蝶结、衣服等部件 | 具有语义意义的对象选区 | 交互分割／语义或实例分割 | Mask、透明 PNG |
| 从扁平图片获得可移动的前后景图层 | 多个 RGBA 图层，可能包含补全内容 | 图层分解／生成式分层 | RGBA 图片、经封装后的图层文档 |
| 将截图恢复成文字框、箭头、流程图 | 可编辑文本与结构化图形 | OCR＋版面分析＋结构重建 | 文本框、图形对象、结构化文档 |

### 1. 描摹不等于恢复原始对象

图像描摹（Image Trace / Bitmap Tracing）的本质是将像素图转换为矢量路径，也叫矢量化（Vectorization）。

它主要处理颜色、明暗和轮廓，不保证理解“这是一顶帽子”或“这是一只手”。一件衣服可能被拆成多个色块，文字通常会变成轮廓，而不是能继续输入的文本框。

描摹结果还可能处于编组或复合路径中，需要扩展、取消编组或按需拆分才能独立编辑。具体步骤取决于软件。普通 JPG、PNG 也没有保留原始设计图层，无法靠取消编组直接恢复。

### 2. 区域分割不等于分层文件

需要区分三个阶段：

1. **确定区域**：哪些像素属于同一个区域，得到标签图或掩码。
2. **提取对象**：把掩码应用到原图，得到带透明背景的图像片段。
3. **组织图层**：保留坐标、层序与命名，保存成 PSD、KRA 或一组 RGBA 图片。

不少研究项目只完成第一步，不能因为示例图显示了不同颜色的区域，就认为它已经支持导出可编辑 PSD。

### 3. 位图图层不等于矢量对象

透明 PNG 或 PSD 中的位图图层可以独立移动、删除和调整，但并没有可编辑的贝塞尔节点。若最终要求修改轮廓节点，需要另做矢量化；反过来，只想移动图片部件，则不必强行转成 SVG。

## 二、分割场景：按输入图片选择路线

### 1. 黑色描边清晰的线稿

目标是把描边围出的区域分开，而不是把黑线自身变成路径。

优先考虑线稿区域分割、容错填充和人工修正。对于闭合轮廓，填充与连通域方法已经能解决部分问题，不一定需要深度学习模型。

主要难点：

- 轮廓存在小缺口，普通填充可能漏到相邻区域。
- 实心黑色阴影和黑色描边不容易区分。
- 细线、抗锯齿和 JPEG 压缩会影响边界判断。
- 两个区域共享同一条描边，拆开后需要决定黑线归属。

**对应选择：LineFiller；希望直接在绘画软件中操作时选 Krita。**

### 2. 没有描边的扁平彩色插画

目标是按颜色边界拆分，例如图标、少色插画、色块清晰的装饰图。

颜色聚类可合并相近颜色，但“颜色相同”和“属于同一个对象”不是一回事。如果希望左右两只同色鞋分别成为对象，还需要空间连通性或人工分组规则。

**对应选择：需要 PSD 时看 LayerDivider；需要 SVG 时看 VTracer；研究插画区域预测时看 DanbooRegion。**

### 3. 有渐变、纹理和阴影的插画

不能把每次颜色变化都当成新的对象。保留过多颜色会产生大量碎片，合并得太强又会丢掉真实边界。

这种场景通常需要在细节保留、区域数量与人工整理成本之间取舍。颜色分层适合底色与效果层编辑，但不保证得到完整的身体部件。

### 4. 实物照片：以琪露诺毛绒玩偶为例

照片中有浅蓝头发、深蓝蝴蝶结、红色领结、蓝裙、白色裙摆和灰色背景，同时存在绒毛纹理、阴影与布料褶皱。

- **按颜色描摹**：可能把同一个部件拆成很多明暗色块；减少细节后会更接近扁平插画。
- **按部件分割**：可尝试交互指定蝴蝶结、头发、裙子等，提取原图中的对应像素。
- **生成式分层**：可以尝试直接生成多个透明图层，但不能默认细节与原图逐像素一致。

这里的路线选择是基于图像特征的判断，尚未对这张照片验证具体工具的效果。

### 5. 用于动画的角色拆件

如果目标是眨眼、摆手或 Live2D 一类动画，仅分割可见像素通常不够。

刘海挡住的额头、裙摆挡住的身体并不存在于原照片像素中。部件移动后要避免露空洞，还需要补绘或生成补全，再进行绑定；补全内容也不等于实物的真实隐藏结构。

## 三、分割方法：各自解决什么问题

| 方法 | 基本思路 | 优点 | 主要边界 |
| --- | --- | --- | --- |
| 洪水填充／连通域 | 在满足条件、彼此连通的像素中扩展区域 | 传统方法，无需训练模型 | 轮廓缺口可能造成泄漏 |
| Trapped-ball Filling | 用具有一定尺度的填充过程，减少细小缝隙造成的区域串通 | 适合存在小缺口的线稿 | 细窄区域与缺口尺度仍影响结果 |
| 颜色聚类＋区域整理 | 按色差分组，再结合空间关系与小区域合并 | 适合平涂插画、少色图形 | 不能仅凭颜色区分语义部件 |
| 分水岭／学习型区域预测 | 基于边界、标记或预测结构划分区域 | 可用于插画区域提取 | 标记与边界质量会影响过分割或欠分割 |
| SAM 类提示分割 | 用点、框等提示指定目标，预测掩码 | 适合交互选部件、保留原图内容 | 不保证逐一拆出所有黑线封闭区域 |
| 生成式图层分解 | 由模型预测多个可合成的透明图层 | 更接近直接获得图层的目标 | 可能改变细节，不是严格的原像素裁切 |
| 矢量化 | 根据区域或轮廓拟合路径 | 可编辑节点、缩放形状 | 不等于语义分割，也不恢复原始图层 |

### “有黑线按线拆，没有黑线按色块拆”能否统一？

可以将它作为组合流程的设计目标，但本次核实的工具中，没有一个可以据此保证对所有图片一键正确处理。

难点不是缺少算法，而是规则本身存在歧义：

- 一条黑线究竟是物体边界、装饰线，还是阴影？
- 缺口是漏画，还是有意连接？
- 同色的两个区域要合为一层，还是分别保留？
- 物体内部的渐变和纹理要不要拆？
- 共享描边应保留在公共线稿层，还是分配给各部件？

更实际的方案是：根据图片选择主方法，允许人工修正，最后再统一导出。传统区域分割、语义部件分割和生成式分层，不应混为一种能力。

## 四、开源工具与模型对照

### 1. GitHub 项目与桌面工具

| 项目 | 核心能力 | 输出／操作形态 | 使用门槛与注意事项 |
| --- | --- | --- | --- |
| [LineFiller](https://github.com/hepesu/LineFiller) | Trapped-ball＋Flood Fill 线稿分割 | 区域分割结果，需另接图层导出 | MIT；当前依赖文件仅列 OpenCV、NumPy；不是完整桌面编辑器 |
| [Krita](https://krita.org/) | 着色蒙版、缺口处理、图层拆分 | 图形界面、位图图层 | 免费开源；需要颜色提示与人工修正，不是任意照片的一键拆件 |
| [LayerDivider](https://github.com/mattyamonaca/layerdivider) | 颜色聚类、相近颜色合并、底色与效果层分解 | 本地界面、分层 PSD | MIT；有 Windows 操作说明，但当前依赖包含 Torch、SAM、ONNX Runtime 等，并不轻量 |
| [DanbooRegion](https://github.com/lllyasviel/DanbooRegion) | 插画与卡通区域预测 | 区域图、研究代码、预训练权重 | Apache-2.0；官方测试环境较旧，部署需要处理兼容性 |
| [VTracer](https://github.com/visioncortex/vtracer) | 黑白／彩色图片矢量化 | SVG；提供桌面程序、CLI 与编程接口 | MIT；适合路径编辑，不保证按语义部件分组 |
| [SD WebUI Layer-Divider](https://github.com/jhj0517/stable-diffusion-webui-Layer-Divider) | 用原版 SAM 分割并封装图层 | SD WebUI 扩展、PSD | Apache-2.0；依赖宿主环境，不建议仅为拆图安装整套 SD WebUI |

#### LineFiller：不要将规划功能当作现有能力

README 明确写出，目前完成的是 Trapped-ball 与 Flood Fill 分割及简单合并。自动补线、特征提取与学习型分组等仍标为进行中，不能根据仓库简介就认定它已提供完整的深度学习拆件流程。

#### LayerDivider：有 PSD，但不等于恢复原始图层

文档描述的核心流程包括 RGB 聚类、按 CIEDE2000 色差合并、模糊平滑、生成底色层，再依据与原图的差异构造效果层。

- `normal`：构造仅包含普通图层的 PSD。
- `composite`：组合普通、滤色、正片叠底、减法和加法等图层。

它生成的是一种新的可编辑分层表达，而不是恢复作者原来绘制时的图层。

#### DanbooRegion：方向贴近，但环境老旧

项目面向插画和卡通区域提取，预训练模型已放入 GitHub 仓库。官方测试环境为 Python 3.6、TensorFlow GPU 1.5、Keras 2.2.4 等旧版本。

适合研究区域预测方法或移植，不宜将旧安装命令直接用于当前日常 Python 环境。

### 2. Hugging Face 模型

| 模型 | 输入与输出 | 适合什么 | 不保证什么 |
| --- | --- | --- | --- |
| [SAM 2.1 Hiera Small](https://huggingface.co/facebook/sam2.1-hiera-small) | 图片＋点／框等提示，输出 Mask；也支持自动掩码生成 | 交互选择照片或插画中的部件 | 不保证沿全部黑线拆区域，不补全遮挡内容，不直接生成 PSD |
| [Qwen-Image-Layered](https://huggingface.co/Qwen/Qwen-Image-Layered) | 图片输入，输出多个 RGBA 图层 | 自动分层、移动与替换图层、继续细分图层 | 不保证遵循固定边界规则，也不能视为逐像素无损拆分 |

两者模型卡均标注 Apache-2.0。开放权重不代表在线计算没有配额，也不代表本地运行只需很少资源。

#### SAM 2.1：分割选区，不重画目标

官方支持正负点、框选等交互方式，也支持自动生成多个候选掩码。利用掩码提取原图像素，可以保留原图可见区域的内容，但边缘质量仍取决于分割与透明度处理。

- [官方 GitHub](https://github.com/facebookresearch/sam2)
- [Hugging Face 模型卡与示例](https://huggingface.co/facebook/sam2.1-hiera-small)

#### Qwen-Image-Layered：原生输出透明图层

官方介绍支持可变层数，也能把已经分出的图层继续细分。官方推理示例采用 CUDA，属于模型推理路线，而不是轻量传统图像处理。

优先使用 [官方在线演示](https://huggingface.co/spaces/Qwen/Qwen-Image-Layered) 判断效果，再决定是否本地部署。调研时接口显示演示处于运行状态，不代表长期可用或没有排队与配额限制。

- [官方项目](https://github.com/QwenLM/Qwen-Image)
- [模型卡](https://huggingface.co/Qwen/Qwen-Image-Layered)

## 五、操作指南：从输入到可编辑结果

以下为文档支持的操作路线与使用建议，不是已在本机验证的安装教程。

### 路线 A：用 Krita 处理黑色线稿

1. 导入线稿，保留原始图层；如果已经有独立线稿层，优先使用它。
2. 选中线稿层，添加 **Colorize Mask（着色蒙版）**。
3. 在目标区域内画颜色提示，执行更新。
4. 检查是否漏填、串区；根据需要调整 **Gap close hint** 等选项。过大的闭合参数也会造成错误。
5. 将着色蒙版转换为绘画图层，再使用 **Layer → Split → Split Layer**。
6. 检查拆出的颜色区域并手动整理；同色区域若仍在同层，需要继续分开。
7. 保存 KRA 工程，按需要导出其他格式。

**边界：**这条路线主要拆分填色结果，不能默认共享黑线已经分别归属到每个部件。若要移动带描边的完整部件，还需处理线稿层。

来源：[Krita Colorize Mask 官方文档](https://docs.krita.org/en/reference_manual/tools/colorize_mask.html)。

### 路线 B：用 LineFiller 做批量或程序化区域分割

1. 准备黑白关系清楚的线稿，保留原图用于后续提取。
2. 依据仓库示例运行已实现的 Trapped-ball＋Flood Fill 分割流程。
3. 检查区域图中的泄漏、漏分和碎片，调整参数或修正线稿。
4. 如果目标是透明图片或 PSD，需要额外将区域转为掩码，再从原图提取内容。
5. 导出时保留原画布坐标与层序，避免所有裁剪片段都失去原始位置。

**边界：**步骤 4—5 是需要补充的集成工作，不是仓库已经提供的完整导出能力。已完成的分割核心无需下载深度学习权重。

### 路线 C：用 LayerDivider 把彩色插画分成 PSD

1. 阅读项目当前安装说明与依赖，使用独立环境；仓库提供 Windows 安装与本地界面启动脚本。
2. 导入图片，先使用较粗的分层设置观察结果。
3. 根据目标调整参数：
   - `init_cluster`：初始聚类数量，增大通常会拆得更细。
   - `ciede_threshold`：控制相近颜色合并。
   - `blur_size`：控制平滑程度，过大会损失细节。
   - `loops`：控制重复合并与处理次数。
4. 选择 `normal` 或 `composite` 输出模式，生成 PSD。
5. 在支持 PSD 的编辑器中逐层检查边缘、颜色和混合模式；不同软件的合成结果可能存在兼容性差异。

**边界：**颜色聚类不保证按“头发、衣服、手脚”命名和分组，也不应为了增加层数而保留大量无用碎片。

### 路线 D：用 SAM 2.1 提取照片中的部件

1. 通过支持 SAM 2.1 的界面或官方示例加载图片。
2. 对目标部件提供正向点或框；若包含多余区域，添加负向点等修正提示。
3. 查看掩码是否包含目标的完整边缘、细窄结构和孔洞。
4. 用掩码提取原图中的目标像素，保存为透明图层。
5. 对其他部件重复操作，整理命名与层序。
6. 如果需要移动部件，检查移动后露出的区域是否需要补绘。

**边界：**模型负责掩码预测，透明图层提取与 PSD 封装需要界面或额外程序支持。自动生成的掩码也不能默认是一套互不重叠、完整覆盖的最终图层。

### 路线 E：在线试用 Qwen-Image-Layered

1. 打开 [官方演示](https://huggingface.co/spaces/Qwen/Qwen-Image-Layered)。
2. 上传允许交给第三方服务处理的图片；敏感图片优先考虑本地方案。
3. 按界面提供的选项设置层数等参数，执行分解。
4. 查看每个图层是否对应预期部件，再将它们合成，与原图比较。
5. 重点检查脸部、文字、细线、材质和透明边缘是否发生变化。
6. 若效果符合用途，再考虑下载结果或进一步细分；需要 PSD 时，确认演示是否提供该导出能力，否则另行组织 RGBA 图层。

**边界：**输出层数不等于正确对象数量；生成结果不能自动视为原始图片的精确恢复。

### 路线 F：需要 SVG 时做矢量化

- **VTracer**：把黑白或彩色图片转换为 SVG，再用矢量编辑器整理路径。
- **Inkscape**：导入图片，打开 **路径 → 位图描摹**，选择黑白或彩色模式并应用，按需取消编组。
- **Illustrator**：典型路线是置入图片、图像描摹、扩展、取消编组；它是商业工具，不是本次开源选型的首选。

Inkscape 的描摹结果会叠在原图上方，可将结果移开进行比较。彩色多次扫描可能产生相互堆叠的对象；并非每个对象都对应一个语义部件。

来源：[Inkscape 描摹指南](https://inkscape-manuals.readthedocs.io/en/latest/tracing-an-image.html)、[Illustrator 图像描摹面板](https://helpx.adobe.com/illustrator/desktop/manage-objects/traces-mockups-symbols/image-trace-panel-options.html)。

## 六、验收标准：怎样判断“拆好了”

不能只看预览图是否像原图，还要检查输出是否适合后续编辑。

- **区域边界**：相邻区域是否串通，细线、孔洞、细小部件是否丢失。
- **对象粒度**：应分开的部件是否独立，同一部件是否被拆成过多碎片。
- **内容保真**：原图细节是否保留；生成式输出是否改变纹理、文字或五官。
- **透明边缘**：是否有白边、黑边、残留背景或明显锯齿。
- **描边归属**：移动部件后，描边是否缺失、重复或留在原处。
- **合成一致性**：按正确位置和层序重新合成后，与原图是否达到用途要求；不能默认所有方法都能逐像素重建。
- **遮挡与补全**：移开前景后是否露空洞；补全区域是否满足使用目的。
- **文件可编辑性**：PSD 是否有实际图层，SVG 是否有实际路径，而不是仅嵌入一张原图。

## 七、选型结论

**先决定编辑对象，再决定算法；先试能解决问题的传统方法，不必直接安装大模型环境。**

- 黑色线稿、轻量分割核心：**LineFiller**。
- 黑色线稿、希望图形界面操作：**Krita**。
- 彩色插画、希望直接获得 PSD：**LayerDivider**。
- 插画区域预测研究：**DanbooRegion**，但需评估旧环境迁移成本。
- 玩偶照片等实物图、希望保留原像素内容：优先试 **SAM 2.1 交互分割**。
- 希望自动生成多个透明图层、接受生成式误差：先试 **Qwen-Image-Layered 在线演示**。
- 最终需要可修改节点的矢量图：**VTracer 或 Inkscape**。

“沿黑线拆、否则沿色块拆”是合理的区域分割目标，但完整交付还包括描边处理、人工纠错和图层导出。当前不宜把任何单一项目描述成对任意图片都可靠的一键恢复方案。
