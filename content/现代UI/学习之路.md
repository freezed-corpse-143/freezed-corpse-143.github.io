# 学习分层

整体路线我建议分成 **8 层**：

```
第一层  Web UI 底层模型
   ↓
第二层  Layout Engineering
   ↓
第三层  Visual Design
   ↓
第四层  Interaction Design / HCI
   ↓
第五层  UI Components & Business Patterns
   ↓
第六层  Motion & Micro-interaction
   ↓
第七层  Design System & UI Architecture
   ↓
第八层  Accessibility / Rendering / Performance
```

Vue、React、Svelte 其实只是横跨这些层的“实现工具”。

# 第一层：Web UI 的底层模型

## 目标

不要再把 HTML/CSS 理解成：

> HTML 写东西，CSS 调样式。

而应该建立：

```
               HTML
                 ↓
                DOM
                 ↓
CSS → CSSOM → Render Tree
                 ↓
               Layout
                 ↓
               Paint
                 ↓
             Composite
                 ↓
               Screen
```

你最终应该能够解释：

- 为什么 `position: absolute` 不占普通文档流？
- 为什么 `z-index: 999999` 有时候还是没用？
- 为什么父元素 `overflow: hidden` 会把东西切掉？
- 为什么 `height: 100%` 经常不起作用？
- 为什么 `min-width: 0` 有时候能解决神秘布局问题？
- 为什么 `transform` 会产生新的 stacking context？
- 为什么动画 `transform` 通常比 `width` 好？

### 必学

```
DOM
CSSOM
Box Model
Normal Flow

Block / Inline
Containing Block
Formatting Context

Intrinsic Size
min-content
max-content
fit-content

Stacking Context
z-index

Overflow
Scroll Container

Layout
Paint
Composite
```

这部分是你的**内功**。

不用一开始把浏览器源码研究明白，但要知道浏览器到底在干什么。

# 第二层：Layout Engineering

## Flexbox

不能停留在：

```
display: flex;
justify-content: center;
align-items: center;
```

要真正理解：

```
main axis
cross axis

flex-basis
flex-grow
flex-shrink

min-width
max-width

intrinsic sizing
available space
free space
```

最后看到：

```
.sidebar {
    flex: 0 0 240px;
}

.content {
    flex: 1 1 auto;
    min-width: 0;
}
```

应该能马上理解它为什么这样写。

## CSS Grid

Grid 是现代 UI 工程师必须掌握的东西。

重点：

```
grid-template-columns
grid-template-rows

fr

minmax()

repeat()

auto-fill
auto-fit

grid-area

implicit grid
explicit grid

subgrid
```

例如：

```
grid-template-columns:
    repeat(auto-fit, minmax(280px, 1fr));
```

要做到一眼知道：

> “这是一个会根据空间自动改变列数的 responsive card grid。”

## Positioning

系统理解：

```
static
relative
absolute
fixed
sticky
```

以及：

```
containing block
scroll container
stacking context
```

然后练习：

```
Sticky Header
Sticky Sidebar
Floating Toolbar
Dropdown
Tooltip
Popover
Context Menu
Modal
Command Palette
```

## Responsive Design

不要只学 breakpoint。

现代响应式设计应该形成：

```
Viewport
   ↓
Page
   ↓
Container
   ↓
Component
```

学习：

```
@media

@container

min()
max()
clamp()

minmax()

auto-fit
auto-fill

vw / vh / dvh
rem
```

例如：

```
font-size: clamp(1rem, 2vw, 1.5rem);
```

逐渐进入：

> Fluid UI

而不是：

> PC 做一个版本，手机再写一个版本。

# 第三层：Visual Design

## Spacing

建立 spacing scale：

```
4
8
12
16
20
24
32
40
48

```

然后开始观察：

```
元素内部距离 → padding
同组元素距离 → gap
不同 section 距离 → section spacing
```

核心概念：

> Proximity creates grouping.

距离本身就在表达信息结构。

## Typography

系统理解：

```

font weight
line height

line length
```

以及：


最后建立自己的 typography scale。

例如：

```

```

重点不是背数字，而是理解：

> **Typography 本身就是信息架构。**

# 第四层：Interaction Design / HCI

这一层决定：

> UI 是“图片”还是“产品”。

推荐把 [Nielsen Norman Group](https://www.nngroup.com/?utm_source=chatgpt.com) 当长期参考资料。

## Feedback

任何操作都应该思考：

```
User Action
     ↓
Immediate Feedback
     ↓
Processing
     ↓
Result
```

例如：

```
Save
 ↓
Saving...
 ↓
Saved ✓
```

或者：

```
Delete
 ↓
Confirm?
 ↓
Deleting...
 ↓
Item removed
 ↓
Undo
```

## UI State

以后设计组件，不要只想：

```
Button
```

而应该想：

```
Button

default
hover
focus
active
disabled
loading
success
error
```

页面也一样：

```
Page

initial
loading
empty
partial
success
error
offline
permission denied
```

这是非常重要的工程思维：

> **UI = State Visualization**

Vue 恰好负责：

```
State → UI
```

所以学完这一层，你对 Vue 的理解都会加深。

## 人体工程与认知规律

重点理解，而不是背定义：

```
Fitts's Law
Hick's Law
Jakob's Law

Cognitive Load
Recognition vs Recall

Affordance
Feedback
Mapping
Constraint

Progressive Disclosure
Error Prevention
Error Recovery
```

例如为什么：

```
Ctrl + K
```

Command Palette 很强？

因为它同时解决：

```
大量功能
+
界面空间有限
+
熟练用户效率
```

# 第八层：Design System

到了这里，你会发现 UI Design 和你之前学的软件架构开始合流。

它们其实很像。

```
Software Architecture        UI Architecture

Primitive Type               Design Token
      ↓                            ↓
   Utility                     Primitive
      ↓                            ↓
  Component                    Component
      ↓                            ↓
   Module                       Pattern
      ↓                            ↓
  Application                     Page
```
## Design Token

例如：

```
Primitive Token

    blue-500
    gray-900
     space-4
    radius-md
        ↓
  Semantic Token
     primary
    background
   foreground
      muted
      danger
        ↓
  Component Token
 button-primary-bg
 dialog-background
   input-border
```

## Headless Component

这是一个非常值得你理解的现代思想。

研究 [Radix UI](https://www.radix-ui.com/?utm_source=chatgpt.com) 一类项目时，不要只看“组件好不好看”。

重点看：

```
Behavior
     +
Accessibility
     +
State Machine
     +
Keyboard Interaction
     +
Focus Management

不负责：

Visual Style
```

于是：

```
Behavior Layer
      ↓
Headless Component
      ↓
Design System
      ↓
Product UI
```

这是非常漂亮的 UI Architecture。

# 四层拆解法

以后看到任何优秀 UI，比如：

```
┌──────────────────────────────────────┐
│ ← Settings                     Save  │
├──────────┬───────────────────────────┤
│ General  │ Profile                   │
│ Account  │                           │
│ Billing  │ Name                      │
│ API      │ ┌───────────────────────┐ │
│          │ │ Jacob                 │ │
│          │ └───────────────────────┘ │
└──────────┴───────────────────────────┘
```

强迫自己从四层分析。

### 第一问：Design

```
为什么 sidebar 是这个宽度？

为什么内容没有铺满？

为什么标题和正文差这么多？

为什么这里 8px，那里 24px？
```

### 第二问：Interaction

```
Save 什么时候 enabled？

保存中是什么状态？

失败怎么办？

离开页面但没有保存怎么办？
```

### 第三问：Engineering

```
Grid 还是 Flex？

Sidebar sticky 怎么实现？

高度怎么处理？

Mobile 怎么响应？
```

### 第四问：Architecture

```
哪些应该成为组件？

哪些是 Primitive？

哪些属于 Pattern？

哪些状态应该由父组件管理？

哪些东西应该进入 Design Token？
```

**这四问练半年，你的 UI 能力会比单纯再学几个前端框架有价值得多。**

# 三套“武功”

我会把整个体系最终压缩成：

```
               UI Engineer

         ┌─────────┼─────────┐
         ↓         ↓         ↓

       眼功        心法       手法
    Design      HCI       Engineering

   Typography   Feedback     HTML
   Spacing      State        CSS
   Hierarchy    Cognitive    JS
   Color        Ergonomics   Browser
   Motion       Patterns     Vue

         └─────────┼─────────┘
                   ↓

              Architecture

             Design Token
             Primitive
             Component
             Pattern
             Design System
```

**眼功**让你知道“好的 UI 长什么样”；**心法**让你知道“为什么这样设计”；**手法**让你知道“浏览器怎么实现”；**架构**让你知道“如何把一次实现变成可复用系统”。
