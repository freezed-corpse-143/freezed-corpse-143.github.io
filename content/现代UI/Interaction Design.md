# Feedback

**核心原则：用户的任何操作，都应该得到即时、清晰的反馈。**

因为用户不知道系统内部发生了什么，只能通过界面反馈来理解"我点了之后发生了什么"。没有反馈，用户就会焦虑、重复点击、怀疑系统坏了。

流程模型：

```
User Action（用户操作）
     ↓
Immediate Feedback（立即反馈）
     ↓
Processing（处理中）
     ↓
Result（结果）
```

关键是**"Immediate"**——哪怕真正的处理需要时间，界面也要**立刻**给出响应，而不是等处理完才更新。

例子 1：保存

```
Save（点击保存）
 ↓
Saving...（立刻显示"保存中"）
 ↓
Saved ✓（完成后显示"已保存"）
```

例子 2：删除

```
Delete（点击删除）
 ↓
Confirm?（先确认，防止误删）
 ↓
Deleting...（删除中）
 ↓
Item removed（已删除）
 ↓
Undo（提供撤销，给用户后悔的机会）
```

这里其实隐含了几个原则：**即时反馈、防止误操作（Confirm）、可恢复（Undo）**。

# UI State

**核心思想：设计组件时，不要只把它当成一个静态的"按钮"，而要把它当成一组状态的集合。**

新手思维：

```
Button
```

工程思维：

```
Button
 ├─ default   默认
 ├─ hover     悬停
 ├─ focus     聚焦（键盘/无障碍）
 ├─ active    按下
 ├─ disabled  禁用
 ├─ loading   加载中
 ├─ success   成功
 └─ error     出错
```

页面也一样，一个页面远不止"正常显示"这一种状态：

```
Page
 ├─ initial          初始
 ├─ loading          加载中
 ├─ empty            空数据
 ├─ partial          部分加载
 ├─ success          成功
 ├─ error            出错
 ├─ offline          离线
 └─ permission denied 无权限
```

这引出了一句非常重要的工程思维：

> **UI = State Visualization（界面就是状态的可视化）**

也就是说，UI 的本质是"把当前的状态用视觉呈现出来"。状态变了，UI 就应该跟着变。

Vue 在这里的角色正好对应：

```
State → UI
```

Vue 的响应式系统负责"状态变化自动反映到界面"。所以理解了这一层，你会更明白 Vue 到底在解决什么问题——它就是在帮你做 **State → UI 的映射**，而你作为设计者要做的，是**把所有可能的状态都想清楚**。

# 人体工程与认知规律

这部分是交互设计的"底层原理"，重点是**理解**，不是背定义。它们解释了"为什么某些设计好用"。

## 经典定律

- **Fitts's Law（菲茨定律）**：目标越大、离得越近，点击越快越准。所以重要的按钮要大、要放在容易够到的地方。
- **Hick's Law（希克定律）**：选项越多，决策时间越长。所以要精简选项、分类、渐进展示。
- **Jakob's Law（雅各布定律）**：用户大部分时间花在别的产品上，所以他们会期望你的产品"跟别人一样"。遵循通用惯例，降低学习成本。

## 认知相关概念

- **Cognitive Load（认知负荷）**：用户脑子能处理的信息有限，界面越复杂，负担越重，越容易出错。
- **Recognition vs Recall（识别 vs 回忆）**：让用户"看见并认出"（识别）比"凭记忆想起"（回忆）容易得多。所以菜单、图标、提示很重要。

## 交互设计的基本原则

- **Affordance（可供性）**：物体/控件本身暗示了它能怎么用。比如按钮看起来像能按。
- **Feedback（反馈）**：前面讲过，操作要有回应。
- **Mapping（映射）**：控件和它控制的对象之间关系要自然、直观。
- **Constraint（约束）**：限制用户只能做合法的操作，防止出错。
- **Progressive Disclosure（渐进式披露）**：先展示核心，复杂功能按需展开，避免一上来就信息爆炸。
- **Error Prevention（错误预防）**：从设计上让错误难以发生（比事后报错更好）。
- **Error Recovery（错误恢复）**：万一出错了，要能轻松恢复（撤销、重试、清晰的错误提示）。

# Ctrl+K(Command Palettle)

Command Palette（命令面板，比如 VS Code、Notion、Linear 里的 `Ctrl+K`）是一个经典例子，它**同时解决了三个矛盾**：

```
大量功能          （功能多）
+
界面空间有限      （放不下那么多按钮）
+
熟练用户效率      （高手不想用鼠标点菜单）
```

- 如果每个功能都做成按钮 → 界面爆炸（违反 Hick's Law、认知负荷过高）。
- 如果藏进多层菜单 → 熟练用户效率低。
- 命令面板：**平时不占空间**，需要时用键盘一调，**输入即搜索**，快速执行任意功能。

它正好用到了前面几个原理：**渐进式披露**（平时隐藏）、**识别优于回忆**（输入时给提示列表）、**为熟练用户优化**（键盘优先）。
