# 对齐

对齐（alignment）指一个数据的起始地址必须是某个数 `A` 的整数倍，`A` 就是对齐要求（alignment requirement）。

例如：
- `char` 对齐 1 字节：地址任意。
- `short`（2 字节）通常对齐 2：地址是 2 的倍数。
- `int`（4 字节）通常对齐 4：地址是 4 的倍数。
- `double`（8 字节）通常对齐 8：地址是 8 的倍数。
- 指针：32 位系统对齐 4，64 位系统对齐 8。

这些要求来自 CPU：**未对齐访问可能变慢，甚至触发异常**（如某些 ARM、SPARC、MIPS 架构）。

## 机器字长 vs 对齐边界

| 概念       | 含义                         | 例子                               |
| ---------- | ---------------------------- | ---------------------------------- |
| 机器字长   | CPU 一次自然处理的位数       | 32 位、64 位                       |
| 自然对齐   | 类型地址必须是其大小的倍数   | `int` 对齐 4，`double` 对齐 8      |
| 栈对齐     | 栈指针按字长或 16 字节对齐   | x86-64 SysV ABI 要求栈 16 字节对齐 |
| 结构体对齐 | 整体大小按最大成员对齐值补齐 | 含 `double` 的结构体整体对齐 8     |

所以：
- 在 32 位系统上，`double` 可能要求 8 字节对齐，**超过机器字长 4**。
- 在 64 位系统上，`int` 仍只要求 4 字节对齐，**小于机器字长 8**。
- 因此“按机器字长对齐”只是常见近似，不是严格规则。

## 为什么常按字长来

教材里画内存布局图时，为了简洁，常把方格画成**机器字大小**，因为：

1. 栈上的局部变量、参数、返回地址通常按字压栈。
2. 数组元素若是指针或 `int`，在 32 位系统上正好一字一个。
3. 字是 CPU 自然读写单位，按字画便于讲“一次访存读一个字”。

但这只是**示意图的简化**。真实结构体里会有填充字节（padding），比如：

```c
struct S {
    char  c;   // 1 字节
    int   i;   // 4 字节，前面补 3 字节
    char  d;   // 1 字节，后面补 3 字节使整体对齐 4
};
```

在 32 位系统上，`sizeof(struct S)` 通常是 12，而不是 1+4+1=6。方格图若按字画，就会显示成 3 个字，每个字里再细分字段和填充。

# 大端序

big-Endian

规则：最高有效字节（MSB）放在最低地址。

```text
高地址
┌───────────────────┐ 0x1003
│       0x78        │  LSB  最低有效字节
├───────────────────┤ 0x1002
│       0x56        │
├───────────────────┤ 0x1001
│       0x34        │
├───────────────────┤ 0x1000
│       0x12        │  MSB  最高有效字节
└───────────────────┘
低地址
```

- 字节序列（低地址->高地址）：`12 34 56 78`
- 书写顺序：`0x 12 34 56 78`

优势：
- 快速判正负：符号位（最高位）固定在第一个字节，计算机只要读取第一个字节就能知道这个数的正负，无需知道数据的完整长度。
- 人类的可读性强：与书写顺序一致。
- 网络传输标准：TCP/IP 协议规定使用大端序作为“网络字节序”，确保不同架构的主机通信时有一个统一的解释标准。

# 小端序

Little-Endian

规则：最低有效字节（LSB）放在最低地址。

```text
高地址
┌───────────────────┐ 0x1003
│       0x12        │  MSB  最高有效字节
├───────────────────┤ 0x1002
│       0x34        │
├───────────────────┤ 0x1001
│       0x56        │
├───────────────────┤ 0x1000
│       0x78        │  LSB  最低有效字节
└───────────────────┘
低地址
```

- 字节序列（低地址->高地址）：`78 56 34 12`
- 书写顺序：`0x 12 34 56 78`

优势：

- 算术运算更顺畅：做加法或乘法时，通常需要从最低位开始计算并向高位进位。小端序让低位字节先被读到，便于计算机尽早开始运算，且多轮乘法的中间结果可以直接写入内存，无需频繁移位。
- 类型转换极简：如果有一个 32 位整数，但只需读取它的低 8 位或低 16 位，在小端序下，同一个内存地址直接当作 8 位或 16 位指针来用即可，读出来的恰好就是地位部分。在大端序下，则需要计算偏移量才能找到低位数据。
- 快速判奇偶：判读一个数是奇还是偶，只需看最低位。小端序把最低字节放在最前面，读第一个字节就能得出结论。
