# paddlenlp+paddlepaddle-gpu 安装

## 环境要求

- Linux（本项目在 WSL 2 上验证，GPU 通过 `/dev/dxg` 转发到 Windows 驱动）
- NVIDIA GPU + 驱动（本项目：Driver 13.3，Compute Capability 8.6）
- Python 3.11（由 uv 管理，`requires-python = ">=3.11"` 实际解析为 3.11.15）
- uv ≥ 0.12


```bash
sudo apt install -y build-essential cmake zlib1g-dev python3-dev python3.12-dev
```

## 安装步骤

1. 初始化虚拟环境

```bash
uv venv --python 3.11
```

2. 安装必要的库

```bash
uv add "paddlepaddle-gpu==2.6.2" \
       "paddlenlp==2.8.1" \
       "aistudio-sdk==0.2.6" \
       "nvidia-cudnn-cu11==8.9.6.50" \
       setuptools \
       pip
```

3. 验证

```bash
uv run python -c "from paddlenlp import Taskflow; print('✅ 导入成功')"
```

安装完成后 `pyproject.toml` 的 `dependencies` 应为：

```toml
dependencies = [
    "aistudio-sdk==0.2.6",
    "nvidia-cudnn-cu11==8.9.6.50",
    "paddlenlp==2.8.1",
    "paddlepaddle-gpu==2.6.2",
    "pip>=26.2.1",
    "setuptools>=84.0.0",
]
```

### 为什么不能用 `uv pip install`

这是最核心的坑。uv 项目模式下：

- `uv pip install` 只把包装进 `.venv`，**不写进 `pyproject.toml` **。
- 下次 `uv run`（或 `uv sync`）发现 lock 与环境不同步时，会**自动重建 `.venv` **，按 `dependencies` 重新安装——由于依赖声明是空的，手动装的包被全部清掉，表现为 `ModuleNotFoundError: No module named 'paddlenlp'`。

正确做法是用 `uv add` 把依赖声明进 `pyproject.toml` 并锁版本。

## 踩坑

### uv 的 venv 不带 setuptools / pip

传统 `python -m venv` 预装 setuptools 和 pip，但 uv 用自己的解析器，创建的 venv 默认两者都不装。而 Paddle 生态的旧版本代码隐式依赖它们：

- `paddle/utils/cpp_extension/cpp_extension.py` 里有 `import setuptools`（paddle 2.6.2 打包缺陷，未声明依赖）
- `paddlenlp/utils/import_utils.py` 里有 `import pip`（paddlenlp 2.8.1 同样未声明）

不装会分别报 `ModuleNotFoundError: No module named 'setuptools'` / `'pip'`。用 `uv add setuptools pip` 补齐。

### aistudio-sdk 版本被装成不兼容的新版

paddlenlp 2.8.1 声明 `aistudio-sdk>=0.1.3`，无上限。uv 会装最新 0.3.9，但 0.3.0 起重构了 API，移除了 `download` 函数：

```
ImportError: cannot import name 'download' from 'aistudio_sdk.hub'
```

锁定 `aistudio-sdk==0.2.6`（0.2.x 最后一代，仍含 `download`）。

### cuDNN 缺失导致 GPU 运算崩溃

`import paddle` / `from paddlenlp import Taskflow` 能成功，但 CUDA 库是惰性加载的，第一次在 GPU 上做运算才触发。paddle GPU 版 wheel 自带 CUDA runtime，但**不打包 cuDNN**，系统若未装 cuDNN 会报：

```
RuntimeError: (PreconditionNotMet) Cannot load cudnn shared library.
```

解决：`uv add "nvidia-cudnn-cu11==8.9.6.50"`（会连带装 `nvidia-cublas-cu11`、`nvidia-cuda-nvrtc-cu11`）。

### nvidia pip 包不创建无版本号符号链接

`nvidia-cudnn-cu11` / `nvidia-cublas-cu11` 装到 `site-packages/nvidia/*/lib/` 后，只有 `libcudnn.so.8`、`libcublas.so.11` 等带版本号的库，**没有 `libcudnn.so` / `libcublas.so` **。而 paddle 的 dlopen 用无版本号精确名查找，找不到。

需要补符号链接（`scripts/run.sh` 已幂等处理）：

```bash
SP=.venv/lib/python3.11/site-packages/nvidia
ln -sf libcudnn.so.8    "$SP/cudnn/lib/libcudnn.so"
ln -sf libcublas.so.11  "$SP/cublas/lib/libcublas.so"
ln -sf libcublasLt.so.11 "$SP/cublas/lib/libcublasLt.so"
```

### WSL 2 的 `libcuda.so` 路径特殊

WSL 2 的 CUDA Driver API 库（`libcuda.so`）由 WSL 的 GPU 转发提供，位于 `/usr/lib/wsl/lib/`，不在 paddle 的默认搜索路径，也不在 `ldconfig` 缓存里（只有 `libcuda.so.1`）。不加路径会报 `libcuda.so: cannot open shared object file`，随后段错误。

`scripts/run.sh` 已把 `/usr/lib/wsl/lib` 加入 `LD_LIBRARY_PATH`。

### 运行 GPU 任务

跑 Taskflow 实例化 / 模型推理 / 训练等需要 CUDA 库的操作时，用仓库内的 wrapper 脚本代替 `uv run`：

```bash
./scripts/run.sh python your_script.py
```

`scripts/run.sh` 做三件事：幂等补齐 nvidia 符号链接、设置 `LD_LIBRARY_PATH`（cuDNN/cuBLAS/WSL libcuda）、转发给 `uv run`。因此即使 `uv sync` 重建了 `.venv`，跑这个脚本也会自动修复。

> 注意：`uv run` 的 `--env-file` 选项**不能**在 `pyproject.toml` / `uv.toml` 里固化（它不属于 `[tool.uv]` 的配置项，只能靠 `UV_ENV_FILE` 环境变量或命令行传入）。这也是为什么用 wrapper 脚本而非 `.env` 文件。

# 模型下载

PaddleNLP 的 Taskflow 首次运行时会自动下载模型到 `~/.paddlenlp/taskflow/`，缓存目录结构：

```
~/.paddlenlp/taskflow/
├── wordtag/                        # NER（Taskflow("ner") 精确模式）
│   ├── model_state.pdparams       # 385 MB
│   ├── config.json / vocab.txt / tags.txt / ...
└── information_extraction/
    └── uie-base/                   # 信息抽取（Taskflow("information_extraction")）
        ├── model_state.pdparams   # 450 MB
        ├── config.json / vocab.txt / ...
```

## 下载坑

自动下载走 `requests`，会读取 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量（本机是宿主机代理 `x.x.x.x:7890`）。实测同一文件：代理 1.5 MB/s，**直连 18.7 MB/s**。450 MB 的 uie-base 走代理只有 2–3 KB/s 且频繁 `ConnectionResetError` / `IncompleteRead` 中断。

解决：用 `curl --noproxy '*'` 直连手动下载到缓存目录，校验 md 5 后 paddlenlp 检测到文件已存在即跳过重复下载。uie-base 的 5 个文件清单（URL 最后一段是保存文件名）：

```bash
DEST="$HOME/.paddlenlp/taskflow/information_extraction/uie-base"
BASE="https://bj.bcebos.com/paddlenlp/taskflow/information_extraction"
curl -s --noproxy '*' -L -o "$DEST/model_state.pdparams"  "$BASE/uie_base_v1.1/model_state.pdparams"   # md5: 47b93cf6a85688791699548210048085
curl -s --noproxy '*' -L -o "$DEST/config.json"          "$BASE/uie_base/config.json"                  # md5: ad8b5442c758fb2dc18ea53b61e867f7
curl -s --noproxy '*' -L -o "$DEST/vocab.txt"            "$BASE/uie_base/vocab.txt"                    # md5: 1c1c1f4fd93c5bed3b4eebec4de976a8
curl -s --noproxy '*' -L -o "$DEST/special_tokens_map.json" "$BASE/uie_base/special_tokens_map.json"    # md5: 8b3fb1023167bb4ab9d70708eb05f6ec
curl -s --noproxy '*' -L -o "$DEST/tokenizer_config.json"   "$BASE/uie_base/tokenizer_config.json"      # md5: 59acb0ce78e79180a2491dfd8382b28c
```

> 大文件下载建议加 `-C -`（断点续传）和 `--retry 5`。各模型的真实 URL 和 md 5 在源码 `paddlenlp/taskflow/*.py` 的 `resource_files_urls` 里可查。
# 实体抽取

两种方案，方案选型：**用 UIE 信息抽取，不用 NER**。两者在本数据上的对比：

| 维度   | `Taskflow("ner")`（wordtag）            | UIE `information_extraction`              |
| ---- | ------------------------------------- | ----------------------------------------- |
| 标签体系 | 预定义细粒度中文标签（`人物类_实体`/`组织机构类`/`世界地区类`…） | 自定义 schema 类型                             |
| 关键问题 | **「特斯拉」被错标为「物体类」**                    | 「特斯拉」正确识别为「组织」                            |
| 输出   | `(词, 标签)` 元组列表                        | `{类型: [{text, start, end, probability}]}` |
用法：

```python
from paddlenlp import Taskflow

ie = Taskflow("information_extraction", schema=["人物", "组织", "地点", "产品"])

ie("2014年1月，特斯拉的董事长兼首席执行官伊隆·马斯克接受采访...")
# [{"人物": [{"text": "伊隆·马斯克", "probability": 0.99, ...}],
#   "组织": [{"text": "特斯拉", "probability": 0.998, ...}], ...}]
```

schema 里的每个字符串就是一个实体类型。低置信度实体（如「中国」0.30、「中」/「美」0.38–0.43）用概率阈值过滤，本仓库取 `0.5`。

# 关系抽取

同一个 UIE 实例用 `set_schema` 切换成关系模式。schema 格式是 `[{主体类型: [关系名列表]}]`，关系名是**客体的角色**：

```python
ie.set_schema([
    {"人物": ["任职机构"]},
    {"组织": ["成立地点", "负责人"]},
])
ie("...")   # 输出三元组：主体 -关系-> 客体
```


输出结构：主体实体携带 `relations` 字典，键是关系名，值是客体列表：

```python
[{"人物": [{"text": "马斯克",
            "relations": {"任职机构": [{"text": "特斯拉", "probability": 0.82}]}}]}]
```

配套一个「关系名 → 客体类型」映射，把客体归类到实体节点（否则客体类型未知）：

```python
RELATION_OBJECT_TYPE = {"任职机构": "组织", "成立地点": "地点", "负责人": "人物"}
```

实测命中：马斯克→任职机构→特斯拉（0.82）、特斯拉→成立地点→上海/上海南汇新城镇工业区（0.65–0.95）、特斯拉→负责人→马斯克（0.73）。

# 时间抽取

**用 NER 的「时间类」标签，不用 UIE**。UIE 的时间实体概率偏低（0.3–0.8）且漏抽（「2015 年」「6 月初」「7 月 10 日」都没抽到），而 NER 的 wordtag 标签覆盖最全。

```python
ner = Taskflow("ner", entity_only=True)
times = [word for word, tag in ner(line) if tag.startswith("时间类")]
```

`时间类_具体时间`（2014 年 1 月）、`时间类`（6 月初、一年后）都会被抽到。再过滤掉**不含数字的相对时间**（「未来」「一年后」），只保留具体日期，得到完整时间线：2014 年 1 月 → 2015 年 → 2017 年 6 月 → 2018 年 5 月 10 日 → 6 月初 → 7 月 10 日 → 2019 年 1 月 7 日 → 2019 年 12 月 30 日上午。

# 实体对齐与清洗

直接抽取有 3 类噪声，`build_kg.py` 内置处理：

1. **人物简称/全称重复**：「马斯克」和「伊隆·马斯克」是同一个人，会导致节点和关系重复。处理：对 `人物` 类型做子串合并，简称映射到全称（「马斯克」→「伊隆·马斯克」）。只对人物类型做，避免误伤地名粒度（「上海」⊂「上海南汇新城镇工业区」不该合并）。
2. **同名多 label 冲突**：UIE 会把「马斯克」同时抽成「人物」(0.998) 和「组织」(0.54)。处理：同名实体只保留置信度最高的那个 label。
3. **自环与重复边**：关系里 source == target 时丢弃；同一 (source, target, type) 去重。

修复前 18 节点 / 5 边（含重复的「马斯克」「伊隆·马斯克」和误判的「组织:马斯克」），修复后 **14 节点 / 4 边**。

# neo4j 社区版坑

`CREATE DATABASE` 是**企业版**特性，社区版执行会报错。社区版只有默认库 `neo4j`（可用 `SHOW DATABASES` 验证，会看到 `neo4j` 和系统库 `system`）。解法：直接用默认库导入，导入前确认库为空（`MATCH (n) RETURN count(n)`）避免污染已有数据。
