# 统一框架

 ```text
推理框架
├─ 接入面：HTTP / CLI / C API / Python API
├─ 请求面：模板、分词、参数校验、输入预处理
├─ 控制面：调度、批处理、生命周期、分布式协调
├─ 状态面：KV Cache、latent、RNG、前缀树、请求状态
├─ 数据面：模型 forward、计算图、算子、kernel
├─ 资源面：显存、内存、mmap、权重驻留、设备间传输
├─ 平台面：CUDA / ROCm / Metal / Vulkan / CPU 等
└─ 工件面：模型格式、配置、权重解析、量化与转换
 ```

 四个项目的根本区别，不是“支持哪些模型”，而是把哪一层当作自己的核心抽象：

 - vLLM：以吞吐为中心的 LLM 请求调度器 + KV Cache 管理器。
 - SGLang：以共享前缀和复杂生成程序为中心的 状态感知调度器。
 - llama.cpp：以可移植、可嵌入为中心的 张量运行时 + 模型运行库。
 - stable-diffusion.cpp：以多组件生成流程为中心的 扩散管线编排器 + GGML 执行器。

“核心引擎”并不等于“无状态层”

 推理框架中真正接近无状态的部分是：

 ```text
输出 = 算子或模型前向（权重，只读输入，显式状态视图）
 ```

 例如：

 - GEMM、RMSNorm、RoPE、Attention kernel。
 - Transformer layer forward。
 - UNet/DiT/VAE 的单次 forward。
 - GGML 计算图执行。
 - logits processor 的部分纯函数操作。

 但完整推理引擎必然有状态：
 
| 状态     | LLM                          | Diffusion                    |
| :----- | :--------------------------- | :--------------------------- |
| 模型常驻状态 | 权重、量化参数                      | DiT/UNet、TE、VAE 权重           |
| 请求状态   | 已生成 token、停止条件               | 当前 latent、采样步、sigma          |
| 推理缓存   | KV Cache、前缀缓存                | conditioning、计算结果缓存          |
| 调度状态   | waiting/running、token budget | 当前阶段、组件驻留状态                  |
| 随机状态   | sampler RNG、历史 token         | 初始噪声、sampler RNG             |
| 运行时状态  | CUDA Graph、workspace         | graph workspace、runner cache |
推理核心引擎进行二分：

 - 计算内核层：尽可能无状态、输入输出明确。
 - 推理状态层：明确状态的所有者、生命周期、分配与回收策略。

## 请求接入层

负责把外部输入变成框架内部请求，不应承担核心计算。
